## 1. Claude Opus 5 — новая модель Claude Code по умолчанию (v2.1.219)

**Зачем.** Всем, кто ежедневно работает в Claude Code: с версии v2.1.219 дефолтная модель — Opus 5, а значит меняются поведение агента и расход токенов.

**Как.** Контекст 1M токенов (и по умолчанию, и максимум), «расширенное мышление» включено по умолчанию, уровни усилий (effort) вплоть до max; отдельный fast mode с тарифом ~$10/$50 за Mtok.

**Подвох.** Ломающее изменение: при effort xhigh/max отключить thinking нельзя, а более высокий effort = выше расход. У самой doc-страницы явной даты нет — 2026-07-23 взята по дате запуска и подтверждена агрегаторами релизов.

## 2. Новые правила контекст-инжиниринга для моделей Claude 5

**Зачем.** Тем, кто пишет CLAUDE.md, промпты и интерфейсы инструментов для агентов: старая привычка «на всякий случай напихать правил» под Claude 5 теперь скорее вредит.

**Как.** Четыре сдвига: доверять суждению модели вместо жёстких правил; выразительные интерфейсы инструментов вместо примеров; прогрессивное раскрытие через skills вместо гор документации заранее; авто-память вместо ручного CLAUDE.md. Anthropic убрали 80%+ системного промпта Claude Code.

**Подвох.** Это рекомендации именно под поколение Claude 5 — на слабых/старых моделях «меньше правил» может выйти боком. Конкретных цифр экономии токенов в статье нет.

`prompting · cost-tokens · skills` · Источник: [blog/Thariq Shihipar (Anthropic)](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models)

## 3. Циклы самопроверки в Claude Code через skills

**Зачем.** Если устали перепроверять за агентом: паттерн, при котором Claude Code сам итеративно проверяет и исправляет результат до того, как отдать вам.

**Как.** Четыре схемы: отдельная проверка (например `/verify`), встроенная проверка внутри skill, цепочка skills (например `/simplify` → `/verify`) и проверка на уровне всего PR. Всё оформляется как обычные skills в Claude Code.

**Подвох.** Верификация надёжна ровно настолько, насколько хороши сами проверки/тесты; лишние прогоны жгут токены. Нужны свежие версии Claude Code с поддержкой skills.

`skills · testing · workflows` · Источник: [blog/Delba de Oliveira (Anthropic)](https://claude.com/blog/building-verification-loops-in-claude-code-with-skills)

## 4. Субагенты против скиллов в Claude Code: когда что применять

**Зачем.** Тем, кто путается, что применять — субагента или skill. Ошибка примитива оборачивается лишним контекстом или недо-контролем над агентом.

**Как.** Субагент = отдельный контекст, свой набор инструментов и модель (для параллельной/изолированной работы); skill = переиспользуемая инструкция в `SKILL.md`, подтягивается по надобности. В статье — примеры из набора на ~53 скилла.

**Подвох.** Материал стороннего блога, а не офиц. документации: часть деталей может устаревать за релизами Claude Code — команды и поведение проверяйте на своей версии.

`subagents · skills` · Источник: [blog/Equipo Duotach](https://duotach.com/en/blog/subagentes-claude-code)

## 6. Хуки, отучающие Claude Code от find/sed/cat в пользу нативных инструментов

**Зачем.** Если Claude постоянно лезет в bash (find/sed/cat) вместо встроенных инструментов и дёргает вас на подтверждения.

**Как.** `git clone` + `./install.sh` (глобально) или `./install.sh --project`; можно поставить один хук: `./install.sh deny-sed-inplace`. Внутри три PreToolUse-хука на Bash: deny-find-chains, deny-sed-inplace, deny-cat-head-tail. Нужен `jq`.

**Подвох.** Эвристика по тексту команды, а не парсинг: не ловит обфускацию (`sed -ni`), может ругаться на упоминание паттерна в комментарии и путается с пробелами в путях. Автор честно предупреждает: «airtight»-защиты это не даёт.

`hooks` · Источник: [github/habibicode](https://github.com/HabibiCodeCH/claude-no-bash-detour)

## 7. fable5-opus5-orchestrator: экономный мульти-агентный оркестратор для Claude Code

**Зачем.** Тем, кто гоняет мульти-агентные сессии и упирается в лимиты: маршрутизация задач по «стоимости» модели экономит токены.

**Как.** `/plugin marketplace add Rylaa/fable-orchestrator`, затем `/plugin install orchestrator@fable-orchestrator` (или вручную скопировать 3 python-хука в `~/.claude/hooks/`). Fable 5 — планы/арбитраж/финальная проверка; Sonnet 5 — реализация, тесты, сбор данных; Opus 5 — эскалация на security. Ledger (`.workflow/LEDGER.md`) переживает компакцию контекста; guard-хуки блокируют делегирование без ledger и не дают закрыть сессию с незакрытыми пунктами.

**Подвох.** Только macOS/Linux, нужны Python 3 и tmux; хуки проверяют факт наличия ledger, а не качество; пункт можно отметить «сделано» без реальной проверки; CPU-эвристика может убить агента, зависшего в долгом внешнем ожидании.

`subagents · cost-tokens · hooks` · Источник: [github/Rylaa](https://github.com/Rylaa/fable5-opus5-orchestrator)

## 8. browser-bridge: управлять реальным залогиненным Chrome из Claude Code через MCP

**Зачем.** Для агентных задач в вебе за логином (SSO, 2FA, внутренние панели), где headless-профиль бесполезен.

**Как.** Собрать server + extension (`npm install && npm run build`), загрузить unpacked-расширение в Chrome, вставить токен, затем: `claude mcp add --transport http --scope user browser-bridge http://127.0.0.1:8765/mcp --header "Authorization: Bearer $(cat ~/.browser-bridge/token)"`. Работает в вашем реальном профиле; только localhost + токен, без открытого debug-порта.

**Подвох.** Неофициальный инструмент; CSP `script-src` мешает eval без баннера; `chrome.debugger` не подцепится, если открыт DevTools; буфер захвата в памяти (по умолчанию 500 запросов/таб); одно подключение расширения за раз.

`mcp · ide-integration` · Источник: [github/vitalysim](https://github.com/vitalysim/browser-bridge)

## 9. clauth: переключение аккаунтов и монитор лимитов Claude Code

**Зачем.** Тем, у кого несколько подписок/аккаунтов и кто упирается в rate-limit посреди работы.

**Как.** `cargo install clauth` (или `curl -fsSL .../install.sh | bash`); переключение `clauth <name>` или клавишей в TUI; 8-вкладочный TUI (Usage/Tokens/Fallback…); MCP-плагин отдаёт инструменты `list_profiles`, `switch`, `delegate`; авто-ротация по цепочке fallback при приближении к лимиту.

**Подвох.** Неофициальный, опирается на реверс хранилища кредов Claude Code; авто-переключение и таймер требуют OAuth-аккаунтов (для API-ключей функционал урезан); на Windows — только через Git Bash/MSYS2.

## 11. cc-session-migrate: перенос сессий Claude Code между машинами

**Зачем.** Если работаете с Claude Code на нескольких машинах: по умолчанию сессии заперты в `~/.claude/` на одном хосте.

**Как.** Поднять сервер `csm agent --server --name server-01`; подключить узлы `csm agent --server-addr <ip>:9827 --auth-token <token> --name my-macbook`; перенос `csm session pull <id-prefix> --from macbook-pro` / `push --to server-01`; затем `claude --resume <uuid>`. Переносит JSONL-логи диалога и метаданные, атомарно, с проверкой SHA256.

**Подвох.** Префикс id — минимум 8 символов; для `claude --resume` нужен полный UUID; требуются исходящие WebSocket-соединения; авто-бэкапы по умолчанию хранятся 30 дней.

`automation · tips` · Источник: [github/bigwhite](https://github.com/bigwhite/cc-session-migrate)

## 12. AgentCost: анализ, на что уходят токены в сессиях Claude Code

**Зачем.** Тем, кто хочет понять, куда именно утекают токены в сессиях агента, и на чём сэкономить.

**Как.** `pip install agentcost-cli` (Python 3.10+), затем `agentcost doctor` и `agentcost smoke -v`. Читает локальные транскрипты Claude Code (`~/.claude/projects/**/*.jsonl`), Cursor, Codex, Ollama; отчёт разбивает расход по типам вызовов (сообщения, инструменты, ответы) в процентах.

**Подвох.** Статус Alpha; логи Claude/Cursor бывают неполными — оценка идёт по длине текста и помечается как «DIRECTIONAL»; цены захардкожены и устаревают (~45 дней, снапшот на 2026-07-24).

`cost-tokens · tips` · Источник: [hn/Kashifdevfe1](https://pypi.org/project/agentcost-cli/0.1.0/)

## 13. claude-code-proxy: запуск Claude Code поверх Codex/Kimi/Grok/Cursor

**Зачем.** Тем, кто любит интерфейс Claude Code, но хочет использовать существующую подписку (ChatGPT/Kimi/Grok/Cursor), а не платить за Anthropic API.

**Как.** `brew install raine/claude-code-proxy/claude-code-proxy` (или install.sh), запустить `claude-code-proxy serve`, затем поднять Claude с переменными: `ANTHROPIC_BASE_URL=http://127.0.0.1:18765 ANTHROPIC_AUTH_TOKEN=unused ANTHROPIC_MODEL=gpt-5.6-sol … claude`. Прокси транслирует трафик Anthropic API в выбранный бэкенд.

**Подвох.** Неофициальный клиент: «может нести риск для аккаунта» по правилам провайдеров; нужен активный платный доступ к выбранной модели; по умолчанию слушает localhost — наружу без файрвола не выставлять.

`cost-tokens · tips` · Источник: [github/raine](https://github.com/raine/claude-code-proxy)

## 14. Как использовать Claude Code и не стать его пассажиром

**Зачем.** Соло-разработчикам и малым командам, которые боятся «разучиться» и потерять контроль, опираясь на агента.

**Как.** Четыре практики автора: (1) структурировать проблему до промпта (непонятная мысль — сигнал остановиться); (2) читать диффы, а не пролистывать (однажды тихая правка сломала разрешение конфликтов синка); (3) допрашивать решения агента («почему тут `Dispatchers.IO`?») как способ учиться; (4) брать ответственность за сбои в проде, а не винить модель. Часть кода автор пишет руками намеренно, чтобы не терять навык.

**Подвох.** Это методология/мнение, без команд и конфигов; переносимость зависит от вашего стека и дисциплины.

`case-study · tips · prompting` · Источник: [blog/jeremiafourie](https://dev.to/jeremiafourie/how-i-use-claude-code-without-becoming-its-passenger-63d)

## 15. OtoDock: self-hosted команда агентов на Claude Code для малой команды

**Зачем.** Небольшой команде/студии, которой нужна приватная (всё на своём сервере) агентная инфраструктура на базе Claude Code, а не облако.

**Как.** `mkdir otodock && cd otodock && curl -fsSLO https://raw.githubusercontent.com/OtoDock/oto-dock/main/scripts/install.sh && bash install.sh`; поднимается на Linux+Docker (мин. 4 ГБ RAM), UI на `http://localhost:8400`. Агенты — это процессы Claude Code/Codex в per-session sandbox-ядрах, общаются через MCP; есть расписания задач, role-based доступ, генерация Word/Excel/PPT/PDF. По README «это видео целиком снял и смонтировал агент OtoDock».

**Подвох.** Fair-source лицензия: бесплатно до 5 пользователей, дальше нужна коммерческая лицензия; требует Docker-сервер; проект свежий (Show HN) — зрелость в проде не подтверждена.

`case-study · subagents · mcp` · Источник: [github/dimitrismrtzs](https://github.com/OtoDock/oto-dock/)
