## 1. Opus 5 в Claude Code по умолчанию урезан до 0.2M контекста — как вернуть 1M

**Зачем.** Тем, кто гоняет Claude Code на Opus 5 по большим кодовым базам: дефолтные 0.2M легко превысить за одну задачу, и модель начинает сжимать/терять контекст.

**Как.** В настройках Claude включить тумблер «Usage Credits» — этого достаточно для полного 1M. Не требуется ни пополнять баланс, ни включать авто-пополнение, ни ставить ненулевой лимит.

**Подвох.** Официального объяснения урезки нет (автор предполагает ставку Anthropic на компакцию контекста у Opus 5). Наблюдение от 2026-07-25 — поведение может измениться; проверяйте реальный лимит через /context.

`cost-tokens · tips` · Источник: [Блог/Wade Tregaskis](https://wadetregaskis.com/claude-opus-5-is-limited-to-a-0-2m-token-context-window-by-default/)

## 2. Claude Code поставил лимиты на свои флоты сабагентов: глубина 3, 20 параллельно, 200/сессию

**Зачем.** Тем, кто строит многоагентные workflow: понимать, почему «упёрлось», и осознанно поднимать/снижать лимиты, не сжигая бюджет.

**Как.** Три env-переменные: `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` (по умолчанию 3; =1 отключает вложенность), `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` (20 одновременно), `CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION` (200 за сессию, /clear сбрасывает счётчик). Хронология: v2.1.217 (21 июля) отключил вложенность и ввёл потолок 20; v2.1.219 (24 июля) вернул вложенность на глубине 3.

**Подвох.** Флаг `--max-budget-usd` НЕ учитывал фоновых агентов до v2.1.217 — если гоняли фоновые сабагенты с бюджетом раньше 21 июля, проверьте реальные траты. Лимит «200 за сессию» нельзя отключить, только поднять.

`subagents · workflows · cost-tokens` · Источник: [Блог/Digital Applied](https://www.digitalapplied.com/blog/claude-code-subagent-depth-limits-budget-caps-2026)

## 3. /fork теперь копирует сессию в фоновую, а делегирование ушло в /subtask

**Зачем.** Тем, кто хочет «ответвить» эксперимент, не теряя основную сессию, и явно управлять делегированием.

**Как.** `/fork` — копия текущего разговора уезжает в фон отдельной сессией, вы не блокируетесь. `/subtask` — новая команда запуска делегированной подзадачи (то, что раньше делал in-session сабагент). Также в релизе: длинные MCP-вызовы (>2 мин) авто-уходят в фон (`CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS`), и появились лимиты на сабагентов и WebSearch за сессию (по 200).

**Подвох.** Это смена привычного /fork — старый сценарий «форк тут же в этой сессии» больше не работает; для быстрой делегации теперь /subtask. Ссылка ведёт на общий changelog (секция v2.1.212 от 17 июля).

`workflows · subagents · tips` · Источник: [Docs/Anthropic](https://code.claude.com/docs/en/changelog#2-1-212)

## 4. Guard: 60 строк PreToolUse-хука, чтобы Claude Code не трогал .env и ключи

**Зачем.** Чтобы агент случайно не переписал/не слил секреты и не лез в migrations/legacy. Полезно всем, кто гоняет Claude Code в acceptEdits/авто-режиме.

**Как.** Скачать guard.py + protected.txt + settings.json в `.claude/`, прописать хук: PreToolUse matcher `Edit|Write|MultiEdit|NotebookEdit`, command `python3 .claude/guard.py`, перезапустить Claude Code. Проверка: `echo '{"tool_name":"Edit","tool_input":{"file_path":".env"},"cwd":"'"$PWD"'"}' | python3 .claude/guard.py` → код выхода 2 = блок сработал.

**Подвох.** Хук НЕ ловит Bash — `rm -rf` и `git reset --hard` проходят мимо (для этого отдельный bash_guard.py). Это не система прав: пользователь может сам отредактировать protected.txt. «Правила — рекомендация, хуки — принуждение».

`hooks · automation` · Источник: [GitHub/avenna01-ceo](https://github.com/avenna01-ceo/claude-code-survival-kr/tree/main/guard)

## 6. ContextSpy: профайлер контекстного окна — видеть, куда утекают токены в Claude Code

**Зачем.** Входные токены в агентных задачах в 20–50× больше выходных — именно они гонят стоимость; ContextSpy показывает, какая часть контекста жрёт больше всего.

**Как.** macOS (Apple Silicon): `brew tap RimantasZ/contextspy && brew install contextspy`; `sudo contextspy install-cert` (один раз); в одном терминале `contextspy start`, в другом `contextspy run claude`; дашборд на http://127.0.0.1:5173 . Альтернатива — направить агента через прокси http://127.0.0.1:8888 .

**Подвох.** Инструмент для разовых сессий оптимизации, не постоянный мониторинг; сырые тела запросов хранятся 7 дней по умолчанию; схема БД может меняться между версиями; ставит локальный CA-сертификат (install-cert).

`cost-tokens · tips` · Источник: [GitHub/RimantasZ](https://github.com/RimantasZ/contextspy)

## 7. fablever: перенести рабочий стиль Fable 5 на любую модель в Claude Code

**Зачем.** Тем, кто хочет более сфокусированное поведение агента, не меняя модель. Ставится за пару команд.

**Как.** `git clone https://github.com/elon-choo/fablever && cd fablever && node install.mjs`, затем перезапуск Claude Code. **Подвох.** Автор приводит измеренные минусы: качество вывода «ничья-до-проигрыша» против обычного Claude у внешних судей, +~14% к стоимости вызова без доказанной экономии на 11 задачах, прирост продуктивности не доказан (A/B намеренно не гоняли). Стиль, а не ум.

`tips · subagents · prompting` · Источник: [GitHub/elon-choo](https://github.com/elon-choo/fablever)

## 8. DESIGN.md: держать дизайн-систему в файле, чтобы Claude Code не изобретал UI

**Зачем.** Тем, кто просит Claude верстать UI и устал от «каши»: одни токены не работают — модель не знает, когда какой цвет уместен.

**Как.** Опишите 8 блоков: тема/атмосфера, палитра с ролями (hex + назначение), типографика, компоненты со всеми состояниями (hover/disabled), правила отступов, тени/высоты, do/don't простым языком, адаптив. Ключевое — явные правила решений («бренд-цвет только на CTA», «у карточек border, не тень»). Подключение: `@DESIGN.md` из CLAUDE.md.

**Подвох.** Токены сами по себе не спасают — без правил «когда/когда НЕ» Claude всё равно ошибётся; файл нужно поддерживать. Статья от 2026-07-26 — разбор идеи, а не готовый шаблон под вашу систему.

`prompting · ide-integration · tips` · Источник: [Блог/aifordevelopers](https://aifordevelopers.substack.com/p/designmd-for-design-in-claude-code)

## 10. Codeman: веб-дашборд для управления сессиями Claude Code в tmux с телефона

**Зачем.** Тем, кто гоняет несколько агентов сразу и хочет контролировать их из браузера/с телефона, включая долгие фоновые прогоны.

**Как.** `curl -fsSL https://raw.githubusercontent.com/Ark0N/Codeman/master/install.sh | bash` (ставит Node.js и tmux при необходимости), затем `codeman web` и открыть http://localhost:3000 . Есть xterm.js-терминалы, вкладки, трекинг токенов/стоимости, Respawn Controller (авто-продолжение при простое, «24+ часа без присмотра»), мобильный UI с QR-входом.

**Подвох.** Модель безопасности — «только для доверенных»: без пароля безопасно лишь на 127.0.0.1; НЕ изолирует пользователей друг от друга (агенты бегут под одним OS-аккаунтом). Сессии по умолчанию с `--dangerously-skip-permissions`; строже — опционально и требует Claude Code 2.1.207+. Windows — только через WSL.

`ide-integration · automation · tips` · Источник: [GitHub/Ark0N](https://github.com/Ark0N/Codeman)

## 11. Observal: локальный реестр и аналитика для скиллов, MCP и агентов Claude Code

**Зачем.** Командам, у которых компоненты разбросаны по репозиториям: единый discovery-слой плюс видимость, что реально используется и приносит пользу.

**Как.** Сервер: `curl -fsSL .../install-server.sh | bash` (Docker Compose: API, web UI, PostgreSQL, ClickHouse, Redis). CLI: `curl .../install.sh | bash` или `uv tool install observal-cli`; затем `observal auth login` и `observal doctor --patch` (ставит телеметрию-хуки). Трекает промпты, тулзы, токены, рейтинги/загрузки, turn-by-turn реплей.

**Подвох.** Тяжёлая инфраструктура: Docker Engine ≥24.0 + Compose v2 для сервера, Python 3.11+ для CLI. Реплей работает только после установки хуков (`observal doctor --patch`). Поддержка ограничена набором харнессов (Claude Code, Cursor, Pi, Copilot, Kiro, Codex, OpenCode).

`mcp · skills` · Источник: [GitHub/Observal](https://github.com/Observal/Observal)

## 13. MCP в проде: проектируй инструменты по бизнес-возможностям, а не по сырым API

**Зачем.** Разработчикам MCP-серверов для Claude Code и агентов: как не завалить модель сотнями сырых тулзов и не отдать ей опасные операции.

**Как.** 1) Инструмент = бизнес-возможность, не инфраструктура: вместо `execute_sql()`/`call_http()` — `request_order_cancellation()`, а домен-сервис за ним держит состояние заказа, лимиты возвратов, владение, идемпотентность, аудит; существующие API оборачивайте тонким адаптером. 2) Каталог: при 50+ тулзах в запросе — проблема; стройте цепочку «цель → поиск возможностей → фильтр прав → ранжирование → модель получает 5–10», каждой записи метаданные (владелец домена, риск, классификация данных, сайд-эффекты, права). 3) Шлюзы делите по зонам доверия/домену (analytics-readonly, developer-tools, customer-service, production-operations) — модель не должна видеть тулзы удаления в проде ради запроса стоимости.

**Подвох.** OAuth решает межпротокольную совместимость, но НЕ авторизацию на уровне тулза, объём согласия пользователя и хранение кредов: валидный токен не доказывает, что агенту можно вызвать этот инструмент и что сумма в рамках политики. Статья общая (AWS-builders), примеры не под конкретный Claude Code.

`mcp` · Источник: [Блог/vidanov](https://dev.to/aws-builders/mcp-in-production-tool-design-catalogs-and-the-gateway-problem-1p52)

## 14. 3 месяца Claude Code рулил блогом: 67 статей, реальные провалы и во что обошлась «автоматизация»

**Зачем.** Соло-предпринимателям и контентщикам, кто мечтает «пусть ИИ ведёт блог сам»: реальная картина с цифрами и граблями, а не хайп.

**Как.** Пайплайн из 8 агентов на расписании: ресёрч → редплан → SEO → написание в голосе автора → факт-чек → генерация картинок → анализ (GA4, Search Console) → публикация в WordPress. Роутинг моделей: Sonnet на оркестрацию/ресёрч/SEO/картинки/публикацию, Opus на письмо и факт-чек (факт-чекер подняли до уровня писателя, чтобы «врун не был умнее проверяющего»).

**Подвох.** «Автоматизация» потребовала кода-обвязки (`check-signoffs.py`, идемпотентный `wp_publish.py`, `audit-schedule-divergence.py`, `check-ai-tells.py`) — вечера инженерии без контента. Провалы: дубли дат публикаций, утечка affiliate-тега неделями, сфабрикованные «я протестировал» прошли факт-чек. Урок: правила — в коде, внешние операции — идемпотентные, креды — с аудитом. Дата: 2026-07-25.

## 15. instar: персистентный агент на Claude Code с памятью, расписанием и Telegram

**Зачем.** Фрилансеру или малой команде, кому нужен всегда-онлайн помощник: отвечает в мессенджере, помнит прошлые разговоры, крутит фоновые задачи по расписанию.

**Как.** `npx instar` (мастер настройки), `instar server start` — и пишите агенту из Telegram/WhatsApp/iMessage. Нужны Node.js 20+, Claude Code CLI и Anthropic API-ключ. Возможности: cron-планировщик с приоритетами, файлы личности AGENT.md, LLM-надзор над внешними операциями.

**Подвох.** Инфраструктура для power-user: работает с `--dangerously-skip-permissions`, безопасность — на поведенческих хуках, не на песочнице; нужен доступ к Claude Code/Codex. iMessage — только macOS (LaunchDaemon + Full Disk Access для фото). Это заготовка, а не готовый бизнес-продукт.

`case-study · automation · tips` · Источник: [GitHub/JKHeadley](https://github.com/JKHeadley/instar)
