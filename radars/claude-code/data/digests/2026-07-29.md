## 1. Сабагенты Claude Code теперь плодят сабагентов: headless-конвейер

**Зачем.** Тем, кто хочет вынести оркестрацию из главной сессии в отдельного агента и запускать полный цикл headless (в CI или ночью).

**Как.** В фронтматтере агента добавить инструмент `Agent` в `tools` (иначе спавнить нельзя) и задать модель. Роли развести по глубине: orchestrator (depth 1) → specifier/planner/builder/verifier/committer (depth 2). Запуск без гейтов: `claude -p "[WORK] <требование> auto" --dangerously-skip-permissions --output-format stream-json`. Лимиты: глубина до 5, 20 одновременно, 200 спавнов/сессию.

**Подвох.** С v2.1.217 вложенный спавн ВЫКЛЮЧЕН по умолчанию — оркестратор молча делает всё сам, ломая разделение ролей. Лечится `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` (или откат на 2.1.216). Вложенные агенты не умеют интерактив (`AskUserQuestion`) — вопросы только на верхнем уровне.

## 2. Claude Code как система, а не окно чата: правила, скиллы, сабагенты, хуки

**Зачем.** Тем, кто устал повторять одно и то же в чате и хочет воспроизводимый процесс вместо разовых промптов.

**Как.** 1) Глобальный `CLAUDE.md` со стандартами («не поддакивай, будь критичен») + языковые файлы (php.md, rust.md, git.md) через прогрессивное раскрытие. 2) Скиллы = markdown-ранбуки под повторяемое (аудит сервера, ревью MR). 3) Сабагенты под параллельные спец-задачи, результаты проверяются централизованно. 4) Хуки (Stop/notification) + кастомный statusline (модель, контекст, лимиты, ветка). 5) Необратимое (commit/push) — только через ручное подтверждение.

**Подвох.** Дорого по токенам: описанный аудит съел ~136M токенов (~$350 по прайсу), потому что агент читает файлы целиком, а не грепом. Для рутины дешевле точечный поиск.

## 3. Скиллы Claude Code ломаются из-за описаний, а не из-за тела

**Зачем.** Авторам скиллов, у которых скилл «не срабатывает» или срабатывает поверхностно.

**Как.** Описание должно отвечать на вопрос «грузить ли скилл прямо сейчас?», а не «что он делает». Плохо: «Проверяет работу: гоняет тесты, смотрит диф…» (процедура → мелкая версия из головы). Хорошо: «Использовать, когда рефактор/багфикс завершён и вы собираетесь отчитаться о готовности. НЕ для правок только в доках» (только условие-триггер → тело грузится). Тест: дать сабагенту лишь список скиллов и реальные задачи; если роутинг мимо — правьте предложения, не тело.

**Подвох.** Пересекающиеся триггеры соседних скиллов дают «затенение» — более глубокий скилл не грузится никогда. Нужен баланс краткости и точности.

## 4. Тихий хук нянчит, громкий хук учит: как хуки меняют поведение агента

**Зачем.** Тем, кто настраивает PreToolUse/PostToolUse-хуки и не понимает, почему агент не перестаёт ошибаться.

**Как.** Тихий автофикс — только для механических всегда-верных правок (форматирование). Если правка требует знания (нейминг, версии) или необратима (прод-деплой) — громкий reject. Пример: PreToolUse на `Write|Edit` вызывает `migration-name.sh`; при нарушении имени миграции (`V012__Billing_AddInvoiceIndex.sql`) выход с кодом 2 блокирует запись и отдаёт агенту текст ошибки — тот сам исправляется. Логируйте срабатывания: частые reject'ы = провал документации.

**Подвох.** Тихие автофиксы создают невидимую зависимость — «хук подтирает вечно», а агент не учится и жжёт токены на повторных ошибках в каждой сессии.

`hooks · automation` · Источник: [Блог/hash01](https://dev.to/hash01/ai-skills-a-silent-hook-babysits-a-loud-hook-teaches-1b5h)

## 5. Opus 5 в Claude Code: уровни усилия и ловушка «thinking по умолчанию»

**Зачем.** Тем, кто гоняет Opus 5 в Claude Code и/или строит запросы через API и хочет управлять стоимостью и усилием осознанно.

**Как.** Модель — `claude-opus-5`. Контекст 1M, вывод до 128K, цена $5/$25 за Mtok. Уровни усилия: low, medium, high, xhigh, max — thinking включён по умолчанию на всех. Выбор в Claude Code: `/model` или `--model claude-opus-5`. Для рутины держите medium, поднимайте на трудные баги/миграции.

**Подвох.** На `xhigh`/`max` попытка выставить `thinking:{"type":"disabled"}` даёт 400 — отключать thinking можно только на `high` и ниже. Проверьте генераторы запросов, которые независимо задают и effort, и thinking.

## 6. Claude Code 2.1.214: пачка фиксов проверки прав + инструмент EndConversation

**Зачем.** Всем, кто гоняет Claude Code с allow-списками прав (особенно headless/CI и на Windows) — эти баги авто-одобряли то, что не должны.

**Как.** Обновиться на 2.1.214+. Исправлено: одно-сегментные правила `dir/**` (напр. `Edit(src/**)`) больше не проваливают авто-одобрение вложенных записей; закрыт обход проверки в Windows PowerShell 5.1; длинные bash-команды (10000+ символов) теперь спрашивают; docker с флагами перенаправления демона (`--url`, `--connection`, `--identity`) требуют подтверждения. Добавлены: инструмент `EndConversation`, heartbeat-прогресс для долгих вызовов, `CLAUDE_CODE_OTEL_CONTENT_MAX_LENGTH`.

**Подвох.** Это набор фиксов безопасности, а не фич — если вы полагались на широкие allow-правила, авто-одобрение стало строже, часть действий начнёт спрашивать. Ссылка ведёт на секцию changelog.

`automation · ci-cd · tips` · Источник: [Docs/Anthropic](https://code.claude.com/docs/en/changelog#2-1-214)

## 7. Claude Code 2.1.217: автодополнение эмодзи и фикс OOM от фигурных скобок в CLAUDE.md

**Зачем.** Тем, у кого CLI падал/тормозил при старте или на длинных MCP-ответах — тут конкретные фиксы, а не косметика.

**Как.** Обновиться на 2.1.217+. Ключевое: brace-expansion в `CLAUDE.md`/`SKILL.md` больше не OOM-убивает CLI при запуске (если в памяти-файлах есть `{...}` — этот баг мог валить старт); устранена утечка памяти на обрезанных выводах MCP-тулзов; авто-компакт снова срабатывает для Opus 4.8 на Bedrock; Windows-автообновление восстанавливает пропавший `claude.exe`; чинятся корпоративные mTLS/TLS/OAuth/proxy в Claude Desktop. Плюс `:heart:`→❤️ автодополнение (выключается `emojiCompletionEnabled`).

**Подвох.** Большая часть — багфиксы под конкретные окружения (Windows, Bedrock, корп-прокси); если вас это не касалось, ценность ниже. Ссылка ведёт на секцию changelog.

## 8. Хороший MCP-сервер vs демо: 4 правила от практика

**Зачем.** Тем, кто пишет MCP-серверы под Claude Code и агентов и хочет, чтобы они не раздували контекст и не творили опасного.

**Как.** 1) Меньше тулзов — каждое определение грузится в контекст на КАЖДЫЙ запрос; лучше несколько широких, чем много узких. 2) Чтение — через resources со стабильными URI (`protocol://resource/path`), они не стоят overhead'а определения; tools — только для изменений. 3) Авторизация fail-closed: неавторизованному токену возвращать 0 тулзов (отсутствие в `tools/list`), а не ошибку; лимиты — деградировать мягко. 4) Помечать операции `readOnlyHint`/`destructiveHint`/`idempotentHint` и делать записи конфликт-безопасными (оптимистичная конкуренция по хешу контента).

**Подвох.** `structuredContent` примерно удваивает размер ответа и может незаметно перекосить метрики/лимиты — пересчитайте лимиты.

`mcp` · Источник: [Блог/freema (Tomas Grasl)](https://dev.to/freema/ive-built-a-handful-of-mcp-servers-heres-what-separates-a-good-one-from-a-demo-4i4f)

## 9. Плагины Claude Code, которые держат агента на jj (Jujutsu) вместо git

**Зачем.** Командам/разработчикам на jj (Jujutsu), у которых Claude Code рефлекторно лезет в git и ломает workflow.

**Как.** `/plugin marketplace add muloka/claude-plugins`, затем `/plugin install [plugin-name]@muloka-claude-plugins` и `/project-setup` в jj-проекте. Плагины: хард-волл git-энфорсмент (PreToolUse-хуки блокируют сырые git-команды), изоляция через jj workspaces, упрощённые коммиты, peer-review (generalist-first с эмерджентными специалистами), tiered-гейтинг прав для автономных сабагентов.

**Подвох.** Требует jj >= 0.31.0 и `jq` — JSON-шаблоны вывода работают только с этой версией и новее. Узкая ниша: только для тех, кто уже на jj.

`workflows · tips` · Источник: [GitHub/muloka](https://github.com/muloka/claude-plugins)

## 10. claude-codex-meight: Claude Code рулит воркерами Codex как нативными сабагентами

**Зачем.** Тем, кто хочет, чтобы архитектурные решения принимал Claude Code, а рутинную реализацию делали параллельные воркеры Codex — с ревью и сбором доказательств до сайн-оффа.

**Как.** Нужны Codex CLI (залогинен) и Python ≥3.10. `git clone https://github.com/keepitmello/claude-codex-meight && cd claude-codex-meight && ./install.sh`. Запуск воркера: `meight start impl-1 --mode worker --brief-file - <<'EOF' … EOF`, затем `meight wait impl-1 --timeout 300`. Диспетчер по умолчанию — сессия Claude Code. Два типа сессий: mates (независимые «спорщики») и workers (реализуют с самопроверкой).

**Подвох.** После таймаута чекпоинта сессии остаются жить (exit code 1) — нужна ручная проверка и рулёжка; авто-восстановления при обрыве сети нет.

`subagents · workflows` · Источник: [GitHub/keepitmello](https://github.com/keepitmello/claude-codex-meight)

## 11. cursor-bridge: гонять Claude Code на подписке Cursor вместо API-кредитов

**Зачем.** Тем, у кого уже есть подписка Cursor и кто не хочет платить отдельно за API-кредиты Anthropic ради Claude Code.

**Как.** `cargo install cursor-bridge`. Запуск: `cursor-bridge` (интерактив), `cursor-bridge "refactor file"` (одноразовый промпт), `cursor-bridge -p "list files"` (pipe). Токен берётся из keychain (macOS) или `CURSOR_TOKEN` (Linux); прокси стартует на случайном порту, подставляет env в Claude CLI и убирает за собой.

**Подвох.** Неофициально — «не аффилировано с Anthropic или Cursor, на свой риск» (риск бана за ToS). Нет песочницы (агент бежит в текущей папке), только один аккаунт, на Linux токен задаётся вручную. В репо всего ~2 коммита — сырое.

`cost-tokens · tips` · Источник: [GitHub/hkc5](https://github.com/hkc5/cursor-bridge)

## 12. Argus: VS Code-кокпит для сессий Claude Code по git-воркдеревьям

**Зачем.** Тем, кто гоняет несколько параллельных сессий агента по разным веткам/воркдеревьям и теряется между терминалами.

**Как.** Поставить Argus + агент (Claude Code 2.1.206+ или Codex), открыть Argus из Activity Bar, добавить репозиторий, выбрать worktree и нажать «New Session» — сессия стартует с этим worktree как cwd. Проекты, вкладки агентов, диффы и терминалы сгруппированы в одном UI; существующие расширения не заменяются.

**Подвох.** Argus только НАХОДИТ существующие воркдеревья — не создаёт и не удаляет их; создание worktree остаётся на вас. Версия 0.1.0 — ранняя.

`ide-integration · workflows · subagents` · Источник: [Веб/PeterDimov](https://marketplace.visualstudio.com/items?itemName=petar-s-dimov.argus-worktree-agent-sessions)

## 15. itr-wala: соло-разработчик научил Claude Code подавать индийскую декларацию (ITR)

**Зачем.** Физлицам и микробизнесу в Индии, кто не хочет платить бухгалтеру (CA) за подачу декларации и готов сам сверить расчёт.

**Как.** Установка через маркетплейс Claude Code: `/plugin marketplace add karanb192/itr-wala` (или shell-скрипт). Даёте Form 16 и AIS — ИИ извлекает данные, а детерминированный Python считает налог и сравнивает старый/новый режим (пример: новый ₹3,00,350 vs старый ₹3,39,730 → экономия ₹42 811). Надёжность: 47 «золотых» тестов + валидатор на 104 теста + property-based фаззер на тысячи случайных деклараций.

**Подвох.** «itr-wala — open-source, а не дипломированный бухгалтер»: при сложных случаях не заменяет консультацию. Рассчитан на тех, кто сам проверит расчёт; только под индийскую налоговую (AY 2026-27).

`case-study · automation` · Источник: [GitHub/Karan Bansal (karanb192)](https://github.com/karanb192/itr-wala)
