## 1. 96,8% токенов Claude Code уходит на перечитывание истории — где утекает и как заткнуть

**Зачем.** Тем, кто удивляется счёту за Claude Code и хочет понять, на что реально уходят токены, прежде чем резать расходы.

**Как.** Автор распарсил локальные логи `~/.claude/projects/` по 32 сессиям: 96,8% токенов — перечитывание истории, ввод пользователя — 0,01%. Один скриншот ≈ 354 shell-команды по токенам; полный WebFetch страницы — в 67 раз дороже, чем вытащить только нужное значение. Рычаги: 1) сперва `grep`/точечный поиск нужного куска файла, потом чтение; 2) меньше скриншотов; 3) со страниц брать только нужные данные, а не весь HTML.

**Подвох.** Пост на японском; цифры — с одной выборки автора (его стиль работы), у вас доля может отличаться. Это диагностика, а не готовый скрипт-оптимизатор.

## 2. JetBrains проверила скилл Ponytail: режет ли он токены Claude Code на самом деле

**Зачем.** Тем, кто ставит «оптимизирующие» скиллы ради экономии и хочет знать реальную отдачу до внедрения.

**Как.** Ponytail — open-source скилл: перед написанием кода агент проходит лестницу «нужно ли это вообще → нет ли уже в кодовой базе → хватит ли стандартной библиотеки → только потом писать минимум». Тест JetBrains (харнес Harbor + 80 парных задач SkillsBench, Claude Code 2.1.201, claude-sonnet-5, medium): факт −15,4% кода, −10,3% стоимости (p=0,004), −11% времени. Важно: скилл сам не включался ни разу — его вшили через `SessionStart`-хук. На переусложнённых задачах экономия кода до −31%, на уже-минимальных ≈0.

**Подвох.** Заявленные автором −54% кода / −22% токенов не подтвердились — реальность вдвое скромнее и сильно зависит от типа задач. Разницы в качестве нет, но и «серебряной пули» нет.

`cost-tokens · skills` · Источник: [Блог/Denis Shiryaev (JetBrains)](https://blog.jetbrains.com/ai/2026/07/ponytail-skill-claude-tested/)

## 3. Amazon случайно сжёг $1,8 млн на Claude за рутинную кодовую задачу

**Зачем.** Всем, кто запускает Claude Code headless/в CI без жёстких лимитов — напоминание поставить бюджеты и алерты до, а не после.

**Как.** По материалу Tom's Hardware: во внутренней аналитике расходов Amazon на ИИ нашли кейс, где менильная кодовая задача превысила бюджет на 860% (~$1,8 млн). Практический вывод: ставьте потолки (`/effort` пониже для рутины, лимиты токенов), заводите отдельный кредитный пул под non-interactive прогоны, мониторьте `$/задачу`, а не только «работает/не работает».

**Подвох.** Это новостная заметка, а не техразбор: точная причина перерасхода (цикл, повторные полные чтения) из статьи не ясна. Сумма — со ссылкой на внутренние метрики, независимо не подтверждена.

## 4. Skills против MCP: когда что использовать в Claude Code (объясняет инженер Google)

**Зачем.** Тем, кто путается, делать фичу скиллом или MCP-сервером, и раздувает контекст сотнями определений тулзов.

**Как.** Различение автора (Tilde Thurium, Google AI): MCP = кухонные инструменты (порезать, смешать) — программный доступ к API и ФС через естественный язык; Skills = поваренная книга (что и когда) — переиспользуемые инструкции в markdown, которые может писать и не-программист. Ключ — прогрессивное раскрытие: агент «знает» про десятки скиллов, но грузит тело только нужного, избегая раздувания контекста, которым страдает MCP с сотнями тулзов. Skills могут учить агента, КАК правильно пользоваться MCP-тулзами.

**Подвох.** Статья концептуальная, без пошагового «if X → выбери Y»; граница на практике размыта, часто нужны оба слоя вместе.

`skills · mcp` · Источник: [Блог/Tilde Thurium (Google AI)](https://dev.to/googleai/skills-vs-mcp-how-ai-tools-have-evolved-3pmk)

## 5. knowledge-rag: локальный RAG-MCP для Claude Code без внешних серверов и ключей

**Зачем.** Тем, кто хочет, чтобы агент искал по большой личной/проектной базе знаний (доки, PDF, код), не сливая её в чужое облако и не платя за эмбеддинги.

**Как.** Установка: `claude mcp add knowledge-rag -s user -- npx -y knowledge-rag` (или через pip + `knowledge-rag init`). Даёт 13 тулзов: `search_knowledge` (гибридный поиск с реранкингом), `add_from_url`, `reindex_documents` и др. Индексирует 1800+ файлов / 39K чанков за <3 мин; 20 форматов (md, PDF, код, Office, Jupyter). Версия v4.6.0 (2026-07-30) перешла на MCP-спеку 2026-07-28.

**Подвох.** Нужен Python 3.11+; на первом запуске качает ~200 МБ моделей эмбеддингов; GPU (CUDA 12) опционален. Локальный индекс = вы сами следите за переиндексацией при изменениях.

`mcp · tips` · Источник: [GitHub/lyonzin](https://github.com/lyonzin/knowledge-rag)

## 6. MCP стал stateless: как мигрировать на спеку 2026-07-28 и не сломать авторизацию

**Зачем.** Авторам MCP-серверов/клиентов под Claude Code, которым пора обновляться на спеку 2026-07-28 без даунтайма.

**Как.** Ключевое: нет `Mcp-Session-Id` и хендшейка — метаданные едут в `_meta` (`io.modelcontextprotocol/protocolVersion`), маршрутизация через заголовки `Mcp-Method`/`Mcp-Name`. Ставить `@modelcontextprotocol/client@2` и `server@2` рядом с legacy `sdk@1.x`. Чеклист из 7 шагов: обязательный `server/discover`; `resultType:"complete"`; `ttlMs`/`cacheScope` на list/read; детерминированный порядок тулзов (для кэша клиента); `subscriptions/listen` вместо HTTP-стримов; убрать `ping`/`logging/setLevel`; коды ошибок (`-32602` вместо `-32002`).

**Подвох.** Безопасность: состояние переехало «на провод» — неподписанный `requestState` = вход под контролем атакующего; подписывайте через `createRequestStateCodec`. Грабли: `LATEST_PROTOCOL_VERSION` всё ещё указывает на 2025-11-25; авто-фолбэк считает провал `server/discover` фатальным — держите отдельные legacy/modern пути.

`mcp` · Источник: [Блог/Rupa Tiwari](https://dev.to/rupa_tiwari_dd308948d710f/mcp-went-stateless-migrating-to-the-2026-07-28-spec-and-proving-it-works-174)

## 7. Локальная merge-queue для параллельных агентов Claude Code — без гонок за push

**Зачем.** Тем, кто гоняет несколько параллельных сессий Claude Code (worktrees/lanes) и ловит конфликты push, лишние тяжёлые сборки и флаки на общих ресурсах.

**Как.** `npm install --save-dev claude-code-merge-queue`, затем `npx claude-code-merge-queue init`. Команды: `land` (ребейз на интеграционную ветку и push через очередь — только одна lane пушит за раз), `build-lock` (сериализует сборки на всей машине), `sync` (fast-forward main), `promote` (в прод), `preview`. Pre-push хук отклоняет прямые пуши — агенты обязаны идти через очередь.

**Подвох.** Нет ревью человеком перед landing — только `checkCommand`. Работает на ОДНОЙ машине, не на флоте. Конфликты ребейза не авто-решаются, а прерывают landing. Медленные тесты становятся потолком пропускной способности.

`workflows · automation` · Источник: [GitHub/funador](https://github.com/funador/claude-code-merge-queue)

## 8. Turbo: воспроизводимый процесс разработки для Claude Code в виде модульных скиллов

**Зачем.** Командам/соло, кто хочет единый предсказуемый конвейер (план → код → тесты/PR) вместо разовых промптов, и уже имеет тесты/линтеры в проекте.

**Как.** Установка интерактивная: в Claude Code попросите «Walk me through the Turbo setup. Read SETUP.md from the tobihagemann/turbo repo». Ядро — цикл из трёх шагов: `/turboplan` (описать, что строим) → `/implement-plan` (или `/implement` для мелочей) → `/finalize` (тесты, полиш, доки, PR). Плюс 70+ скиллов на дебаг, апгрейд зависимостей, аудит проекта; всё — plain markdown поверх нативных примитивов (git, ФС, встроенные тулзы).

**Подвох.** Лучше всего работает, если в проекте уже есть тесты/линтеры/форматтеры/pre-commit хуки. Нужен GitHub CLI и внешние сервисы (для peer-review в Claude-издании — ChatGPT Plus). Прямо сказано: «мусор на входе — мусор на выходе», вульгарный план он не спасёт.

`skills · workflows` · Источник: [GitHub/tobihagemann](https://github.com/tobihagemann/turbo)

## 9. Гейт-промпт для тест-кейсов: заставить ИИ сначала думать, потом генерить тесты

**Зачем.** QA/разработчикам, кто просит Claude «напиши тесты» и получает поверхностные кейсы без граничных/негативных сценариев.

**Как.** Структура (автор Ujjwal Kumar Singh): Фаза 1 «Гейт» — разбор требований по 5 разрывам (функциональный, системный/границы, UX-логика, безопасность/приватность, интеграции), агент выкатывает вопросы/допущения и печатает «Phase 1 complete. Reply PROCEED». Фаза 2 — только после вашего PROCEED — 12–20 кейсов с точными литералами (HTTP 422/403, границы 0/-1/null, ассерты на мутацию/не-мутацию состояния), явный teardown и блок идемпотентности/конкурентности. Для чата — раскидывать фазы по разным тредам.

**Подвох.** В длинных диалогах контекст «плывёт» и точность падает — автор советует two-thread подход (отдельный тред на верификацию). Это каркас промпта, а не готовый скилл.

`testing · automation · prompting` · Источник: [Блог/Ujjwal Kumar Singh](https://dev.to/beinghumantester/stop-asking-ai-for-test-cases-building-a-gate-controlled-sdet-prompt-2den)

## 12. Claude сам себе ставит PostToolUse-хук

**Зачем.** Тем, кто осваивает хуки жизненного цикла и хочет живой пример, как агент сам генерит и подключает PostToolUse.

**Как.** Видео (канал ZazenCodes): демонстрируется, как в сессии Claude Code довести агента до того, чтобы он сам прописал PostToolUse-хук (срабатывает после каждого Tool-вызова) — типовые применения: авто-формат после Write/Edit, запуск линтера/тестов, пинг. ## 13. «Claude Code — это по сути while-цикл»: как устроен агентный цикл под капотом

**Зачем.** Тем, кто хочет понять принцип работы агента (а не только команды), чтобы осмысленно строить свои воркфлоу/хуки/скиллы.

**Как.** Видео (Tech With Tim): агент раскладывается на цикл — LLM решает следующий шаг, вызывает инструмент (Bash/Read/Edit/поиск), получает результат, снова идёт в модель — пока не выполнено условие остановки.
