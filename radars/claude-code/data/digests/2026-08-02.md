## 1. mcp-recall: сжатие выводов MCP-инструментов, чтобы сессия жила дольше

**Зачем.** Тем, кто гоняет Claude Code с «тяжёлыми» MCP-инструментами (Playwright-снимки, ответы GitHub API, SQL-выборки, большие файлы) и упирается в переполнение контекста.

**Как.** `npx mcp-recall install` (или `bun add -g mcp-recall && mcp-recall install`, проверить `mcp-recall status`). Дальше он перехватывает выводы MCP и Bash, а полный результат достаётся из локального SQLite по запросу.

**Подвох.** Сжимает только MCP-инструменты и Bash — встроенные Read/Grep/Glob идут как есть. Нужен рантайм Bun и установленный Claude Code, данные только локально (не синхронизируются), сборка мусора вручную (`mcp-recall gc`).

`mcp · cost-tokens` · Источник: [github/sakebomb](https://github.com/sakebomb/mcp-recall)

## 2. Melodic Software: маркетплейс переиспользуемых плагинов для Claude Code

**Зачем.** Командам и одиночкам, кто не хочет писать скиллы/хуки с нуля — берёшь готовый плагин (интейк тикетов, ревью, PR, ченджлоги и т.п.) и используешь.

**Как.** `/plugin marketplace add melodic-software/claude-code-plugins`, затем `/plugin install <plugin-name>@melodic-software`. Обновление каталога — `/plugin marketplace update melodic-software`. Есть Skill Cheat Sheet (маппинг задача→плагин).

**Подвох.** Внешние/личные плагины по умолчанию выключены — нужен явный `/plugin enable`; в managed-настройках требуется allowlist. Каждый плагин проходит «migration gate», даты релиза на странице не видно.

`skills · hooks · mcp` · Источник: [github/melodic-software](https://github.com/melodic-software/claude-code-plugins)

**Подвох.** Мёрж — только с явного разрешения (никогда автоматом); деструктивные git-команды и «зелёные» правки тестов заблокированы. Сон машины, обрыв сети или интерактивный запрос могут застопорить прогон.

`automation · skills` · Источник: [github/aigorahub](https://github.com/aigorahub/elves)

## 4. claude-control: диспетчеризация Claude Code с телефона + флот фоновых агентов

**Зачем.** Тем, кто хочет управлять сессиями Claude Code не сидя за ноутом — с телефона, плюс держать пул фоновых агентов с контролем расходов и «канон»-раскаткой через пул-реквесты.

**Как.** `git clone … && cd claude-control && ./install.sh`, прописать проекты в `~/.claude-control/projects.yaml`; команды в Telegram `/sessions`, `/agents`, `/new <project> <text>` или CLI `claude-rc`.

**Подвох.** Для полного функционала нужен Linux с `systemd --user` (на macOS только CLI), Claude Code CLI ≥2.1.51 с подпиской, `yq` v4 и включённый lingering; опирается на research-preview `claude remote-control`.

`automation · workflows` · Источник: [github/dewil](https://github.com/dewil/claude-control)

## 5. Agent-Manager: tmux-TUI для параллельного запуска Claude Code и других агентов

**Зачем.** Тем, кто гоняет несколько агентов одновременно и путается в терминалах — один экран со статусами, диффами и перезапуском «умерших» сессий.

**Как.** `brew install yoanwai/tap/agent-manager` (или install.sh через curl), запуск `agent-manager`. Пробел — отправить промпт без захода в сессию, Ctrl+R — дифф с построчными комментариями; сессии умеют стартовать в изолированных git-worktree.

**Подвох.** Учёт стоимости пока не реализован, мышью не поводить, межагентного общения нет; авто-детект статуса — только для пяти известных инструментов.

`ide-integration · tips` · Источник: [HN/YoanWai](https://github.com/YoanWai/agent-manager)

## 9. Claude Code через OpenRouter: понятная инструкция по настройке

**Зачем.** Тем, кто хочет из Claude Code дотянуться до других моделей (в т.ч. бесплатных/open-source) через один шлюз с общим биллингом и видимостью расходов.

**Как.** Поставить Claude Code, взять ключ OpenRouter, задать env: `ANTHROPIC_BASE_URL="https://openrouter.ai/api"`, `ANTHROPIC_AUTH_TOKEN="$OPENROUTER_API_KEY"`, пустой `ANTHROPIC_API_KEY`; затем `/logout`, перезапуск, проверка `/status`.

**Подвох.** По докам самого OpenRouter связка «гарантированно хорошо» работает только с моделями Anthropic; маршрутизация через разных провайдеров может добавить задержки и стоимости.

`tips` · Источник: [Dev.to/shreshthgoyal](https://dev.to/shreshthgoyal/claude-code-openrouter-the-setup-guide-that-actually-explains-things-1d6o)

**Зачем.** Тем, кому нужен self-hosted агент а-ля Claude Code без привязки к одной модели (Claude, GPT, Gemini, Ollama, любой OpenAI-совместимый API) — и типобезопасный фреймворк для своих агентов.

**Как.** `pip install pydantic-deep` (или install.sh через curl). Фишки: форк «живого» прогона на параллельные ветки с ИИ-судьёй, общий список задач у команды агентов, память в MEMORY.md, поддержка MCP-серверов.

## 12. Magpie: превращаем ИИ-агента в бухгалтера для малого бизнеса

**Зачем.** Малым командам, которые хотят, чтобы агент помогал вести бухгалтерию, но без права «выдумывать» проводки и без прямого доступа к базе — все записи атрибутируемы и аудируемы.

**Как.** `git clone … && cd magpie && go install ./cmd/magpie && magpie --store .magpie init`. Дальше через JSON-команды: создать счёт, завести клиента, записать выплату, вести план счетов.

**Подвох.** Нет парсинга QuickBooks (данные нормализуешь в JSON сам), нет оплаты счетов, сверки, налогов и закрытия периода; нет UI и слоя аутентификации; софт до 1.0.

`case-study · automation` · Источник: [HN/kyle-visner](https://github.com/kyle-visner/magpie)

## 13. DispatchSEO: SEO-менеджер для Claude Code (ресёрч → PR → трекинг позиций)

**Зачем.** Небольшим студиям и техническим фрилансерам на git-сайтах, кто хочет отдать рутину SEO агенту: ресёрч ключей, черновики страниц как PR, отслеживание выдачи.

**Как.** `sh start.sh` (Windows: `.\start.cmd`) — поднимает всё разом. Нужен coding-агент (Claude Code или Codex), Docker (~1 ГБ RAM) и доступ к Google Search Console.

**Подвох.** Только git-сайты — WordPress не поддерживается; расписания работают, только пока машина не спит; нужен Docker и GSC — не для нетехнического владельца бизнеса.

## 14. zfrontpage: ежедневная газета, которую собирает routine Claude Code + GitHub Pages

**Зачем.** Наглядный шаблон, как собрать полностью автономный ежедневный контент-продукт (газета/дайджест/новостной лендинг) на бесплатном стеке — близко к тому, как устроен и этот радар.

**Как.** Три части: `master-prompt.md` (устав/дизайн, сменяемый между моделями), утренний routine-агент Claude Code (веб-поиск → проверка → HTML) и GitHub Actions как «ворота» — публикует в `main`, только если менялся контент, и отказывается, если тронуты файлы-правила.

**Подвох.** Агент не пушит в `main` напрямую — только через одобрение workflow; веб-доступ ограничен `WebSearch` (прямой HTTP к сайтам закрыт); файл-память («морг») чистится вручную, а allowlist в workflow должен совпадать со всеми создаваемыми файлами, иначе публикация не пройдёт.

`case-study · automation` · Источник: [HN/Lywald](https://github.com/Lywald/zfrontpage/)

## 15. Oryxflow: дешевле и надёжнее гонять аналитику данных из Python и Claude Code

**Зачем.** Тем, кто регулярно считает отчёты/аналитику (в том числе руками агента) и обжигался на «протухших» промежуточных данных — нужна воспроизводимость без серверов.

**Как.** `pip install oryxflow`. Пересчитывает только затронутые задачи при изменении кода/параметров/данных, ведёт lineage. Плагин добавляет в Claude Code команды `/oryxflow:migrate`, `/oryxflow:init-project`.

**Подвох.** Это не про продакшн-расписание (для этого Airflow/Prefect/Dagster), не про дашборды экспериментов (MLflow/W&B), без распределённого выполнения и данных больше памяти; проверяет воспроизводимость, а не корректность.

`case-study` · Источник: [HN/oryxintel](https://github.com/oryxintel/oryxflow)
