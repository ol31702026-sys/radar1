## 1. Официальный плагин Slack для Claude Code: MCP-сервер + 6 навыков + 5 команд

**Зачем.** Командам, которые живут в Slack: Claude Code читает и пишет в Slack прямо из терминала — дайджест канала, поиск обсуждения, черновик анонса или стендапа, не уходя в браузер.

**Как.** `/plugin install slack@claude-plugins-official` (официальный маркетплейс). Внутри — MCP-сервер (поиск сообщений/файлов/каналов, отправка и планирование, канвасы), 6 навыков и 5 slash-команд: сводка каналов, поиск темы, анонс, стендап, мульти-канальный дайджест.

**Подвох.** Нужны права к рабочему пространству; записи в каналы проверяйте глазами. Данные уходят в Slack API.

`skills · mcp · slash-commands` · Источник: [github/slackapi](https://github.com/slackapi/slack-skills-plugin)

## 2. Ruflo — мета-оркестратор агентов поверх Claude Code и Codex

**Зачем.** Тем, кому нужен не одиночный агент, а конвейер (ревью, тесты, документация, security-скан) без ручного жонглирования инструментами.

**Как.** Лёгкий плагин: `/plugin install ruflo-core@ruflo`. Полный CLI: `npx ruflo@latest init wizard` — векторная память (AgentDB/HNSW), swarm-координация, фоновые воркеры, мульти-провайдерность.

**Подвох.** Лёгкий плагин НЕ даёт полного цикла (`memory_store`, `swarm_init` только в CLI). Проект тяжёлый, роевые прогоны жгут токены. Оценивайте под задачу, а не по звёздам.

`workflows · subagents · automation` · Источник: [github/ruvnet](https://github.com/ruvnet/ruflo)

## 3. Видео: «фабрика ПО» из агентов на связке Codex + Claude Code

**Зачем.** Тем, кто хочет автоматизировать весь цикл задачи — от тикета до готового PR, а не отдельный промпт.

**Как.** Owain Lewis (25 июля) строит пайплайн, где агенты «берут тикеты, уточняют их, реализуют изменение, гоняют тесты и ревью и открывают pull request». Ключ — явные шаги и точки проверки.

**Подвох.** Видео-разбор (дословных команд нет — страница YouTube не отдаётся авто-извлечению). Автономный конвейер требует тестов как критерия готовности и человеческого гейта на merge.

`workflows · ci-cd · automation` · Источник: [youtube/Owain Lewis](https://www.youtube.com/watch?v=AbpyqAfxZ8c)

## 4. Борис Черни: главное в работе с Claude Code — дать ему проверять себя

**Зачем.** Ориентир от главы Claude Code: на больших автономных задачах решает не «магический промпт», а декомпозиция и способность агента верифицировать себя.

**Как.** Черни поднял GitHub-раннер с Mac и пустой Swift-проект и попросил Claude переписать Electron-приложение на Swift, снимать скриншот и сравнивать «пиксель за пикселем», пока не совпадёт. Задача крутилась 2+ недели.

**Подвох.** Это интервью (YC Startup School, разбор у Daring Fireball, 2 авг), не гайд. Гербер замечает: пиксель-в-пиксель чинит нативность, но не UX — верификация хороша ровно настолько, насколько хорош её критерий.

`tips · workflows` · Источник: [blog/Daring Fireball](https://daringfireball.net/linked/2026/08/02/cherny-claude-swift)

## 5. Unreal-MCP: Claude Code управляет Unreal Engine — 61 инструмент и скриншоты

**Зачем.** Геймдев-разработчикам на Unreal: агент инспектирует и меняет проект в редакторе — расставить объекты, собрать Blueprint, поправить C++ и сразу увидеть картинку.

**Как.** `npm install -g unreal-mcp-cli`, затем `unreal-mcp-cli install-plugin ./YourProject`, `login`, `open`. 61 инструмент (акторы, Blueprints, ассеты, редактор, уровни, C++, скриншоты). Пример: «поставь три куба и свет» → actor-create + screenshot-viewport для проверки.

**Подвох.** Бета. Нужен Unreal 5.5+ (тест 5.7/5.8), C++-проект и GPU-редактор (скриншоты не работают в headless). Только десктоп.

`mcp · ide-integration` · Источник: [github/IvanMurzak](https://github.com/IvanMurzak/Unreal-MCP)

## 6. Gauge: куда уходит подписка Claude Code — локальный трекер расхода

**Зачем.** Тем, кто упирается в лимиты и не понимает, что их съедает: расход по 5-часовым окнам, дням, моделям и проектам (и отдельно Codex).

**Как.** Разово: `npx github:joey-io/gauge`. В statusline: `npm i -g github:joey-io/gauge` + команда statusline в `~/.claude/settings.json`. Считает по «API-list-equivalent», учитывает вложенные субагенты.

**Подвох.** Это оценка по эквиваленту API-цен, а не реальный счёт по подписке. Проект свежий (★3).

`cost-tokens · tips` · Источник: [github/joey-io](https://github.com/joey-io/gauge)

## 7. claude-agent-pack: 20 специализированных субагентов с общей памятью

**Зачем.** Кто хочет взять собранный «отдел», а не заводить агентов по одному: планирование, реализация по языкам, гейты качества (код/безопасность/производительность), доставка.

**Как.** `git clone …/claude-agent-pack.git`, `bash ./claude-agent-pack/install.sh`, `bash <pack>/scripts/setup-project.sh <project>`. Вызов через 29 slash-команд (`/implement`, `/plan`, `/review-pr`, `/hotfix`, `/debug`). Решения хранятся Markdown-ом в `memory/` и переживают сессии.

**Подвох.** Свежий и малозвёздный (★5); «enterprise» — по факту шаблон под подгонку. Много агентов = кратный расход токенов.

`subagents · slash-commands · workflows` · Источник: [github/chuckplayer](https://github.com/chuckplayer/claude-agent-pack)

## 8. ccbeam: «телепорт» сессии Claude Code между машинами

**Зачем.** Кто работает с нескольких машин: начал на ноутбуке — продолжил на сервере/в облаке без «перескажи, на чём мы остановились».

**Как.** `npm i -g ccbeam`, опц. `ccbeam install-shell`. В сессии `/ccbeam:up [device]:[path]` и `/ccbeam:home`. Через SSH-хост или песочницы E2B; переносит транскрипт и незакоммиченные git-изменения.

**Подвох.** Креды не форвардятся; целевая машина должна быть на том же коммите. Node 18+ (20.18.1+ для облака). Только личные устройства. Проект новый (★1).

`workflows · ide-integration · tips` · Источник: [github/sahilmahendrakar](https://github.com/sahilmahendrakar/ccbeam)

## 9. Hamza: шлюз, маскирующий секреты и PII до отправки в модель

**Зачем.** Кто боится утечь ключ или клиентские данные в облачную модель: «egress-гейт» вырезает чувствительное ДО провайдера, сохраняя связность запроса.

**Как.** Три детектора (секреты, PII на Presidio, кастомные значения). `HAMZA_POSTURE=MASK docker compose up -d --build`, затем `export ANTHROPIC_BASE_URL=http://127.0.0.1:10000`.

**Подвох.** Не замена контролю доступа и юр.договорам — доп. слой. Нужны Docker Compose и Java 25/Maven. Очень свежий (★1) — сперва на тестовых данных.

`automation · tips` · Источник: [github/softcane](https://github.com/softcane/hamza)

**Подвох.** Короткое видео на испанском (дословный конфиг не приводим — YouTube не отдаётся авто-извлечению). Механизм хуков — в доках Claude Code; команду проверяйте под свой кейс.

## 11. Tuneloop: локальная аналитика сессий Claude Code — цена за смёрженный PR

**Зачем.** Улучшить процесс, а не просто считать токены: видно, во что обходится результат (доллар на смёрженный PR), где агент буксует и что даёт переделки.

**Как.** `npx tuneloop analyze` — сканирует `~/.claude/projects`, строит локальную SQLite-базу, поднимает дашборд на `http://localhost:4319`. Размечает сессии по типу работы, сложности и автономности.

**Подвох.** Базовая аналитика локальна, но «умная» разметка требует своего LLM-ключа (~$6 за ~100 сессий). Оценки затрат модельные, не биллинг.

`cost-tokens · prompting · tips` · Источник: [github/tuneloop](https://github.com/tuneloop/tuneloop)

## 12. Кейс: рефинансировал ипотеку — и собрал MCP по данным Банка Англии

**Зачем.** «Ближе к земле»: бытовая задача (следить за ставкой перед рефинансом) стала переиспользуемым инструментом — Claude сам достаёт свежие цифры вместо ручного гугления.

**Как.** `npx -y boe-mcp`, прописать MCP-сервером в `settings.json` Claude Code. 9 функций: базовая ставка (текущая/история/на прошлую дату), ряды IADB (SONIA, курсы, ипотека), заседания MPC. stdio или HTTP, с кэшем.

**Подвох.** Данные только по Великобритании. Проект персональный и молодой (★2) — агрегатор публичных данных, не фин.совет.

`case-study · mcp` · Источник: [github/moureauf](https://github.com/moureauf/boe-mcp)
