## 1. Claude Code 2.1.221: Focus-режим в VS Code, маскировка секретов в песочнице, мгновенные плагины

**Зачем.** Тем, кто живёт в Claude Code каждый день: меньше визуального шума в VS Code, безопаснее прогонять команды в песочнице, а плагины и фоновые прогоны работают без ручных шагов.

**Как.** Focus-режим — переключатель в меню чата или `Ctrl+Alt+F`; показывает пофазовую сводку с живым индикатором работающего инструмента. Маскировка секретов — `mode: "mask"` для sandbox-credential файлов (Linux/WSL): команда читает sentinel-копию, а прокси подставляет реальное значение только на egress. Плагины из `/plugin` активируются сразу; фоновые сессии сами коммитят и пушат, следуя git-инструкциям из CLAUDE.md.

**Подвох.** Маскировка файлов работает только на Linux/WSL — на macOS откат к полному запрету (`deny`). Это набор точечных изменений релиза, а не крупная фича.

`ide-integration · workflows · automation` · Источник: [docs/Anthropic](https://code.claude.com/docs/en/changelog#2-1-221)

## 2. Anthropic принёс спецификацию MCP 2026-07-28: stateless-ядро, MCP-приложения, туннели

**Зачем.** Тем, кто подключает MCP-серверы к Claude Code: новый стандарт упрощает деплой серверов и делает подключение к корпоративным и приватным инструментам безопаснее.

**Как.** Stateless request/response ядро (можно serverless/edge); MCP Apps рендерят UI прямо в диалоге; MCP-туннели (research preview) дают доступ к серверам внутри частной сети без публичного порта; авторизация по OAuth 2.0/OIDC (раздача коннекторов через Entra/Okta). В каталоге 950+ серверов.

**Подвох.** Пост — анонс, без деталей реализации (спецификация — на modelcontextprotocol.io). Туннели пока research preview. Claude Code в посте прямо не разбирается, но именно он потребляет MCP-серверы.

`mcp` · Источник: [blog/Anthropic](https://claude.com/blog/bringing-mcp-2026-07-28-to-claude)

## 3. codex-claude-code-config: 29 принципов, 40+ хук-скриптов и набор скиллов для дисциплины агента

**Зачем.** Тем, кто хочет не по одному хуку прикручивать, а взять собранный «регламент безопасности» для агента — особенно на реальных репозиториях, где важно, чтобы агент не снёс лишнего и не слил ключи.

**Как.** Плагином — `claude plugin install https://github.com/AnastasiyaW/claude-code-config`; глобально — `python ~/claude-code-config/scripts/install_hooks.py --global`; локально — `--local`. Внутри: 29 принципов, 40+ хуков (secret-leak-guard, git-auto-backup, handoff-reminder…), 15+ скиллов с RU/EN-роутингом, шаблоны CLAUDE.md.

**Подвох.** Хуки ловят случайный дрейф и человеческие ошибки, но не агента, который целенаправленно обходит правила — граница доверия всё равно на человеке. Репозиторий большой, требует подгонки под стек.

## 5. Capshelf: общие навыки агента между репозиториями с локфайлами на проект

**Зачем.** Тем, кто ведёт несколько репозиториев и устал копировать навыки/настройки Claude Code руками — общий источник правды без риска, что изменение в одном месте молча сломает остальные.

**Как.** `brew install genged/tap/capshelf`. В проекте: `capshelf init --data https://github.com/acme/agent-config`, `capshelf add security-review`, публикация правки — `capshelf promote security-review -m "..."`. Локфайл `capshelf.lock.json` пиннит элементы по хэшу; другие проекты обновляются только по явному `capshelf update`.

**Подвох.** `validate`, `diff`, `doctor`, `journal` ещё в роадмапе — полноценного аудита конфигурации пока нет. Проект свежий.

`skills` · Источник: [github/genged](https://github.com/genged/capshelf)

## 6. MoFlo: локальная оркестрация Claude Code — семантическая память, маршрутизация, гейты

**Зачем.** Тем, кто хочет, чтобы Claude Code помнил контекст между сессиями и сам подбирал агента под задачу — при этом всё локально, ничего не уходит в облако.

**Как.** `npm install --save-dev moflo`, `flo init`, перезапустить Claude Code — память включается сама. Проверка — `flo healer`. Прогнать issue от начала до конца — `/flo <issue-number>`. Память — 384-мерные эмбеддинги; гейты заставляют искать в базе знаний до похода по файлам и регистрировать работу до спавна субагентов.

**Подвох.** Работает только с Claude Code (CLI, IDE-расширения, web) — это НЕ интеграция с Claude Desktop и не работает с другими клиентами. Проект молодой.

`workflows · automation` · Источник: [github/eric-cielo](https://github.com/eric-cielo/moflo)

## 9. cctap: подсветит и приведёт к той сессии Claude Code, которой нужен ты

**Зачем.** Тем, кто гоняет 3-4+ сессий Claude Code разом и теряет момент, когда агент остановился и ждёт — cctap делает «затыки» видимыми и мгновенно доступными.

**Как.** `npx @chipmates/cctap install-hooks`, затем `npx @chipmates/cctap keys setup`. Команды: `cctap` — прыгнуть к сессии, которой нужен ты; `cctap 2` — к сессии №2; `cctap top` — полноэкранный список; `cctap notify on` — desktop-уведомления. Ноль рантайм-зависимостей.

**Подвох.** Работает только через хуки Claude Code; в неуправляемых терминалах лишь подсвечивает сессию (переключаться руками). Нужен Node 22+ (Windows — только WSL). Не аффилирован с Anthropic.

`automation · tips` · Источник: [github/chipmates](https://github.com/chipmates/cctap)

## 12. Claude Code читает секреты в открытую, даже когда Read запрещён

**Зачем.** Всем, кто полагается на deny-правила Claude Code как на защиту секретов: это ложное чувство безопасности, и важно понять почему.

**Как.** Автор навесил deny на `Read(*)` для файла секретов, но Claude через `Bash(*)` выполнил `grep` и вытащил `JWT_SIGNING_KEY` и `CAPTCHA_SECRET`. Перечислить в denylist все способы прочитать файл (`sed`, `xxd`, `strings`…) невозможно. Рекомендация: секреты — в vault, а не в denylist; данные могут храниться до 30 дней.

**Подвох.** Это про архитектурное ограничение denylist, а не баг версии; «починить» правилами нельзя — только вынести секреты из репозитория.

`tips` · Источник: [blog/Dejan (jankovd)](https://jankovd.substack.com/p/claude-can-read-your-secrets)
