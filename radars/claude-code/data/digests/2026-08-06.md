## 1. Claude Code 2.1.222: worktree-изоляция теперь по-настоящему изолирует, ultraplan убран

**Зачем.** Если вы гоняете фоновые/worktree-сессии и сабагентов (в т.ч. в CI или на общем репозитории), апдейт закрывает риск: изолированная сессия больше не может случайно снести незакоммиченные изменения в основном чекауте.

**Как.** Обновиться до 2.1.222 (`claude update`). Заодно починены: PreToolUse auto-allow хуки, обходившие ограничения инструментов в фоновых задачах; зависание проверки связи за HTTPS-прокси; `/usage`, приписывавший расход MCP-серверам. Фича `ultraplan` удалена — перейдите на обычный план / `/code-review`.

**Подвох.** Это релиз багфиксов, а не новых возможностей: ярких фич нет, но для тех, кто параллелит агентов, изоляция критична. Полный список — на странице changelog (#2-1-222).

## 2. CostClaw: локальный аудит расхода токенов Claude Code одной командой

**Зачем.** Фрилансеру или маленькой команде, которая платит за Claude Code из своего кармана и хочет понять, за что именно уходят деньги, без ручного разбора логов.

**Как.** `npx costclaw audit` — прогоняет логи на диске и оценивает setup по 6 «столпам», подсвечивая 4 типа потерь: промахи промпт-кэша (полная цена вместо 1/10), реактивные циклы одного и того же инструмента, дорогую модель (Opus) там, где хватит дешёвой, и сессии, «переросшие» кэш. Всё локально, без аккаунта.

**Подвох.** Аудит бесплатный, но авто-исправления (`costclaw optimize`) — платно ($39 разово). Даёт диагноз, но чинить конфиг всё равно вам.

`cost-tokens` · Источник: [hn/ucsandman](https://www.costclaw.io/)

## 3. Curie: собрать, протестировать и выкатить Claude-Code-агента от ноутбука до Kubernetes

**Зачем.** Тем, кто хочет вынести Claude-Code-агента из терминала в прод-сервис и боится, что в кластере не окажется нужной версии Python, утилиты или креда.

**Как.** Установка: `curl -fsSL https://raw.githubusercontent.com/curie-eng/curie/main/get-curie.sh | bash`. Три уровня одним и тем же бандлом: `curie skill up` (быстрый цикл), `curie local up` (очередь→воркер→песочница), `curie cluster up` (Kubernetes, версии по git). Внутри — Langfuse и Slack.

**Подвох.** Проект молодой (Apache-2.0, ~6★), Teams/email-интеграции ещё в планах; это инфраструктура под агентов, а не готовый агент — придётся вникать в очереди и кластер.

`automation · ci-cd · subagents` · Источник: [hn/athusoo](https://github.com/curie-eng/curie)

## 4. peri: быстрый агент на Rust, который читает конфиг Claude Code как есть

**Зачем.** Если хочется более лёгкий/быстрый локальный агент, но жалко бросать уже настроенные skills/hooks/MCP из Claude Code — peri переиспользует их без миграции.

**Как.** Установка: `curl -fsSL https://raw.githubusercontent.com/konghayao/peri/main/scripts/install.sh | bash` (или PowerShell на Windows), запуск — `peri`. Совместимость через Agent Client Protocol (ACP); работает с любым LLM, авто-компакт по мере роста токенов.

**Подвох.** Это отдельный агент, а не плагин к Claude Code; «совместимо» не значит «идентично» — часть поведения CC может отличаться. ~142★, активная, но чужая разработка.

`skills · ide-integration` · Источник: [hn/KonghaYao](https://github.com/KonghaYao/peri)

## 5. hud-mode: компактный HUD поверх Claude Code вместо стены вывода инструментов

**Зачем.** Тем, кого раздражает бесконечная прокрутка tool-calls и кто хочет видеть только суть плюс держать под глазом расход токенов в реальном времени.

**Как.** `npm install -g adrida/hud-mode && hud install`. Запуск: `hud`, `hud "промпт"`, `hud -r` (продолжить), `hud claude "fix the CI"` (выбрать движок). Есть тумблер в полный нативный TUI. Нужен Node ≥18 и установленный claude/codex/opencode.

**Подвох.** Обёртка молодая (~8★); это эргономика/косметика вывода, а не новые возможности агента.

`ide-integration · tips` · Источник: [hn/adam_rida](https://github.com/adrida/hud-mode)

## 6. agents-inc: собирать сабагентов Claude Code из атомарных навыков через CLI

**Зачем.** Кто устал копипастить одинаковые промпты сабагентов между проектами и хочет собирать их из готовых навыков под конкретный стек.

**Как.** `npx agents-inc init` → выбрать технологический стек → отметить skills в сетке → получить скомпилированных сабагентов. Монорепо на Bun/Turborepo: CLI, веб-редактор, API-воркер, доки. MIT.

**Подвох.** Совсем ранний (~5★), каталог навыков небольшой; реальную пользу увидят те, у кого много однотипных агентов.

`subagents` · Источник: [github/agents-inc](https://github.com/agents-inc/agents-inc)

## 7. agent-skills: библиотека из 330 переиспользуемых навыков для Claude Code, Codex и Gemini

**Зачем.** Кто не хочет писать каждый навык с нуля и ищет готовый «магазин» кроссагентных skills, работающих не только в Claude Code.

**Как.** Каждый skill = контракт `SKILL.md` + точка входа `run.sh` + проверка `sanity.sh`; `./deploy.sh` рассылает их в настроенные «дома» агентов. Примеры: Surf (браузер через ChatGPT), Watch (понимание видео), Extractor (док → дерево фактов), Scillm (прогон/сабагенты/DAG).

**Подвох.** Личная «мастерская» автора (~5★), навыки разной зрелости и заточены под его окружение; часть — экзотика. Это не курированный официальный маркетплейс.

`skills` · Источник: [github/grahama1970](https://github.com/grahama1970/agent-skills)

## 8. Bourdon: один файл общей памяти для Claude Code, Codex и Cursor

**Зачем.** Кто параллельно работает в нескольких агентах (CC/Codex/Cursor) и устал заново объяснять каждому одно и то же — общий слой памяти синхронизирует контекст между ними.

**Как.** `npm i -g bourdon` или `pip install bourdon`, дальше — quickstart из доков. Бесплатно и open-source для self-host (лицензия BUSL-1.1 → Apache-2.0 через 4 года), федерация между агентами не платная. Управляемый хостинг — «скоро».

**Подвох.** Молодой проект, часть материалов датируется полевыми тестами весны 2026; «recognition-first» — красивая идея, но надёжность синхронизации на своих данных придётся проверять самому.

`tips` · Источник: [hn/RADLAB](https://bourdon.ai)

## 15. «Сессия, которая синхронизировала сама себя»: перенос сессий Claude Code между аккаунтами (кейс)

**Зачем.** Кто работает с несколькими аккаунтами Claude Code на одной машине или переносит разговоры между папками проектов и не хочет потерять историю и состояние.

**Как.** Инструмент `claude-code-sessions` (craigstoller) переносит сессии и синхронизирует записи в сайдбаре между аккаунтами; ключевой инсайт — в разговоре нет привязки к аккаунту, «перенос» = создание строки-указателя на общий транскрипт. End-to-end проверено 3 августа 2026.

**Подвох.** Только Windows; «refuse-first» намеренно отказывает при расхождении identity-файлов и при запущенном Claude Desktop. Автор честно пишет о ранних ошибках в замерах — инструмент нишевый и требует аккуратности.

`case-study · workflows` · Источник: [hn/craigstoller](https://github.com/craigstoller/claude-code-sessions/blob/main/docs/the-session-that-synced-itself.md)
