## 1. Claude Code 2.1.223: закрыт обход проверки Bash-команд, wildcard для маркетплейс-репозиториев

**Зачем.** Всем, кто пускает Claude Code с авто-разрешениями на Bash: обход проверки означал, что «безопасная» команда могла тайком выполнить лишнее. Плюс полезно тем, кто раздаёт плагины на команду — маркетплейс-репозитории теперь можно разрешать/блокировать пачкой на уровне GitHub-организации.

**Как.** Обновиться: `claude update`. Ключевое в 2.1.223: фикс обхода разрешений Bash (команды, «добитые» невидимым Unicode, больше не прячут части от проверки); `"owner/*"` в managed settings маркетплейса; фикс песочницы на Linux, когда `sandbox.filesystem.denyWrite` накрывал рабочую папку; `/review` теперь алиас `/code-review` (облачный разбор — `/code-review ultra`).

**Подвох.** Это релиз безопасности и багфиксов, а не витрина фич. Но именно такие правки стоит накатывать сразу — особенно при включённых авто-allow правилах.

`slash-commands · automation · tips` · Источник: [docs/Anthropic](https://code.claude.com/docs/en/changelog#2-1-223)

## 2. mcp-use v2: MCP-фреймворк переписан с нуля под stateless-спецификацию 2026-07-28

**Зачем.** Тем, кто пишет свои MCP-серверы и мучился с session-id и sticky-роутингом при деплое: в stateless-модели любой запрос может прийти на любой инстанс, поэтому проще масштабировать и класть на edge.

**Как.** `npm install mcp-use @mcp-use/client @mcp-use/inspector`. Пакет разбит на части (`mcp-use`, `@mcp-use/client`, `@mcp-use/agent`, `@mcp-use/inspector`). Убраны `initialize`-хендшейк и `Mcp-Session-Id`; маршрутизация по заголовкам `MCP-Protocol-Version` / `Mcp-Method` / `Mcp-Name`. Заявлено: +27% throughput, −55% холодный старт, −82% размер установки.

**Подвох.** v2 договаривается вниз со старыми серверами, но нативный v2 больше не эмулирует API v1 — старые интеграции смотреть по отдельной v1-документации. Это про разработку MCP, а не готовый сервер «из коробки».

`mcp` · Источник: [blog/luigipederzani](https://manufact.com/blog/mcp-use-v2)

## 3. OneCLI: open-source шлюз, который держит секреты подальше от ИИ-агентов

**Зачем.** Тем, кто боится давать агенту живые API-ключи (утечёт в лог, в промпт, в чужой инструмент). OneCLI разрывает эту связь: секрет хранится в шлюзе, а агент про него не знает.

**Как.** `curl -fsSL https://onecli.sh/install | sh` (или Docker Compose, дашборд на `http://localhost:10254`). Секреты хранятся зашифрованными (AES-256-GCM), расшифровываются только в момент запроса и подставляются по совпадению host/path. Есть scoped-токены на нескольких агентов и интеграция с Bitwarden.

**Подвох.** Быстрый старт — локальный режим без аутентификации; для команды нужен Google OAuth и связка Rust-gateway + Next.js + PostgreSQL. Это инфраструктура, которую надо поднять и поддерживать.

`mcp · automation` · Источник: [github/onecli](https://github.com/onecli/onecli)

## 4. Uber открыл ADR — мониторинг безопасности для Claude Code, Cursor и Codex

**Зачем.** Командам, которые дали разработчикам Claude Code / Cursor / Codex и хотят видеть, что агенты реально делают, и ловить опасное поведение — а не надеяться на промпты. Покрывает все 17 задокументированных техник атак на агентов.

**Как.** Репозиторий на Python (`uv sync`). Четыре блока: сбор и нормализация телеметрии из разных инструментов (macOS/Linux/Windows); тестирование безопасности через ADR-Bench (303 задачи, 133 MCP-сервера); детект угроз двухагентной схемой (быстрый триаж + глубокий разбор); предотвращение действий (пока не открыто). Статья принята на MLSys 2026.

**Подвох.** Энтерпрайз-инструмент под масштаб Uber: нужно строить сбор телеметрии и разбираться в схеме. Соло-разработчику избыточно; блокирующая часть (prevention) в open-source ещё не выложена.

`automation · testing · mcp` · Источник: [github/uber](https://github.com/uber/ADR)

## 5. code-auditor-mcp: архитектурные инварианты блокируют правку агента прямо в цикле

**Зачем.** Тем, у кого агент раз за разом нарушает договорённости кодовой базы (слои, границы модулей, запрещённые импорты). Правило проверяется в момент записи файла и блокирует нарушение — не отчёт постфактум.

**Как.** `npm install -g code-auditor-mcp` → `code-audit install --agent all` (ставит MCP-сервер и блокирующий хук). Для Claude Code как плагин: `claude plugin marketplace add BenAHammond/code-auditor-mcp`. Блокирует правки на уровне/выше заданного порога серьёзности. Языки: TS, JS, Go.

**Подвох.** Настоящее блокирование — только в Claude Code (там потребляется вывод хука); в Cursor хук «fire-and-forget», поэтому лишь совет. Нужно завести и поддерживать набор правил-инвариантов.

`mcp · refactoring · testing` · Источник: [github/BenAHammond](https://github.com/BenAHammond/code-auditor-mcp)

## 6. contexer: запоминает архитектурные решения из сессий и подставляет их в следующей

**Зачем.** Всем, кто устал в каждой новой сессии заново объяснять «у нас так принято»: почему выбран стек, что нельзя трогать, какие соглашения. Contexer делает это постоянным слоем памяти между сессиями.

**Как.** `uv tool install contexer` → `contexer install` (сам находит и подключает совместимых ассистентов: Claude Code, Cursor, Codex, Gemini CLI). Локальная консоль `contexer ui` показывает, что скармливается агентам. Есть живой бенчмарк против рукописных rule-файлов.

**Подвох.** Open-source версия — по одному разработчику на машине; общий слой на команду (Contexer Teams) пока в раннем доступе. Польза зависит от дисциплины фиксации решений.

`prompting · workflows` · Источник: [github/bhargavamin](https://github.com/bhargavamin/contexer)

## 7. fak (Fused Agent Kernel): стабильный кэш, компакт контекста и восстановление после падений

**Зачем.** Тем, кто жжёт токены на промахах промпт-кэша и упирается в лимит контекста в длинных сессиях. Ядро стабилизирует префикс запросов и само сбрасывает устаревшую историю.

**Как.** Запуск с Claude Code: `fak guard -- claude` — поднимает приватный шлюз-ядро и направляет туда Claude без смены креда/ключей. Плюс политика вызова инструментов на allow-list (~362 нс на решение) и resume после краша. Язык — Go (1.26+).

**Подвох.** Проект до 1.0, интерфейсы меняются; в `CLAIMS.md` каждая возможность помечена `[SHIPPED]`, `[SIMULATED]` или `[STUB]` — часть заявленного пока не «боевое».

`cost-tokens · mcp` · Источник: [github/anthony-chaudhary](https://github.com/anthony-chaudhary/fak)

## 8. claude-toolkit: версионируй и раскатывай свои правила/агенты/скиллы Claude Code по проектам

**Зачем.** Тем, кто ведёт несколько репозиториев и хочет держать свои rules/agents/skills Claude Code в одном месте, а не копипастить `.claude` из проекта в проект.

**Как.** Новый проект — `/start.md` через Claude Code; существующий — `/canon` синхронизирует апдейты с three-way merge и вопросом по каждому изменённому файлу. Fleet-режим катит неизменяемые релизы через транзакционный WAL с CI-валидацией. В комплекте — 34 правила, 14 агентов, 25 скиллов.

**Подвох.** Репозиторий сильно заточен под воркфлоу автора: под себя придётся вычищать правила и править манифесты — это не универсальный дистрибутив «поставил и поехал».

`skills · ci-cd` · Источник: [github/dewil](https://github.com/dewil/claude-toolkit)

## 9. wallfacer: менеджер терминальных сессий Claude Code — найти и возобновить любую

**Зачем.** Тем, кто держит десятки сессий Claude Code и не может вспомнить, в какой была нужная ветка мысли. wallfacer сводит их в один список с поиском и тегами.

**Как.** `brew install pradipta/wallfacer/wallfacer` (или `go install github.com/pradipta/wallfacer@latest`). TUI-браузер и CLI: переименовать/пометить/сгруппировать сессии, полнотекстовый поиск по промптам и метаданным, удаление в корзину или полностью. Работает поверх нескольких агентов (Claude Code, Cursor CLI, Kiro, Codex).

**Подвох.** Это органайзер над логами сессий, а не бэкап и не редактор истории. Ставится через Homebrew/Go — под чистый Windows без них сложнее.

`workflows · tips` · Источник: [github/pradiptasarma](https://github.com/pradipta/wallfacer)

## 10. Aident Loadout: скилл, дающий Claude Code доступ к 1000+ приложений (Gmail, Slack, Notion…)

**Зачем.** Тем, кто хочет, чтобы Claude Code не только писал код, но и делал реальные действия во внешних сервисах — завести задачу в Linear, разослать письма, обновить Notion — без ручной сборки MCP под каждый сервис.

**Как.** Установка скилла: `npx -y @aident-ai/cli@latest update --skill-only`. Дальше агент знает, когда дёргать Aident Loadout: 1000+ приложений и 27000+ действий, секреты через Aident Vault, по каждому действию — аудит-след.

**Подвох.** Это интеграция с платформой Aident (не «родной» плагин Claude Code): вы завязываетесь на их сервис и хранилище кредов. Для чувствительных данных оцените модель доверия к внешнему vault.

`skills · mcp · automation` · Источник: [github/Aident-AI](https://github.com/Aident-AI/aident-skill)

## 14. Кейс: агентство из Мадрида собрало свой мультиязычный сайт на Claude Code (52% коммитов)

**Зачем.** Маленькой студии/агентству — реалистичное разделение труда с Claude Code: где он ускоряет, а где нужен человек. Трезвый ориентир вместо «сайт сам себя напишет».

**Как.** Стек: Astro 5, Tailwind v4, деплой на Dokku. Claude Code закрыл «объёмную работу»: повторяющиеся компоненты, скрипты, систему переводов на 5 языков со скриптом-проверяльщиком (валит CI без перевода), middleware нормализации URL, генератор sitemap. Итог: из 639 коммитов 331 (52%) — в паре с Claude Code. Люди держали дизайн, архитектуру и финальное ревью.

**Подвох.** Заголовок с Hacker News («no human interaction») вводит в заблуждение — в статье прямо сказано: люди принимали все ключевые решения и ревьюили каждое изменение. Вывод авторов: нужен системный человеческий контроль.

`case-study · automation` · Источник: [blog/Soamee](https://soamee.com/en/blog/en-we-built-website-with-claude-code)

## 15. Кейс: соло-разработчик за 85 часов и $100 собрал мобильную игру с Claude Code

**Зачем.** Соло-разработчику/инди без большого бюджета — ориентир, что реально успеть в одиночку с Claude Code на greenfield-проекте и во что это обходится.

**Подвох.** Автор сам называет это «идеальными условиями»: greenfield, один человек, нет легаси. «800 часов» — его оценка, не замер; на зрелой кодовой базе выигрыш обычно скромнее.
