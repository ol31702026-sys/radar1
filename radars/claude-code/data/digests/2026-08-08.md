## 1. Claude Code за неделю: свои self-hosted-раннеры, обмен сообщениями между сессиями и снятый лимит субагентов

**Зачем.** тем, кто держит Claude Code открытым весь день — быстро понять, что реально изменилось за неделю, не перечитывая шесть changelog'ов.

**Как.** ключевое: `claude self-hosted-runner` запускает web/desktop/mobile-сессии на ваших машинах и контейнерах (Team/Enterprise); плагины теперь ставятся из zip по HTTPS с опциональным SHA-256-пиннингом (источник `archive`); кросс-сессионный `SendMessage` + `ListAgents` для обнаружения агентов (macOS/Linux); `claude-opus-5` — новый дефолт с 1M контекста; снят лимит в 200 субагентов на сессию; закрыт ряд дыр обхода песочницы.

**Подвох.** часть фич (self-hosted, кросс-сессии) только на платных планах и/или macOS/Linux — под Windows не всё; Havoptic — сторонний трекер, перед тем как завязывать процессы на конкретную версию, сверьтесь с официальным changelog.

## 2. Когда жать /clear, а когда /compact: практическая шпаргалка по контексту Claude Code

**Зачем.** всем, у кого длинные сессии и Claude «тупеет» к концу — держать качество и не жечь токены на раздутую историю.

**Как.** правила: новая несвязанная задача → `/clear` и свежий бриф; та же задача, но окно забивается выводом инструментов → `/compact`, пока есть запас; модель упрямо держит неверное предположение → `/clear` (оно засело в истории); авто-компакт уже в однозначных процентах → почистить и переписать бриф руками (2 минуты, лучше авто-сводки). Мантра: «чисти на границах задач, а важное клади в файл (CLAUDE.md), а не в сводку».

**Подвох.** порог деградации ~32k — наблюдение автора, а не бенчмарк Anthropic; на разных задачах он свой. Ручной бриф требует дисциплины — легко забыть и потерять контекст.

`prompting · cost-tokens · tips` · Источник: [blog/Tim Schipper](https://tim-schipper.nl/en/blog/claude-code-context-management)

## 3. anthropometer (amtr): btop-подобный монитор контекста и денег для сессий Claude Code

**Зачем.** тем, кто не понимает, почему сессия жрёт контекст и деньги, и хочет увидеть утечку, а не гадать по одному числу из `/context`.

**Как.** ставится без зависимостей: `curl -fsSL https://raw.githubusercontent.com/arian-shamaei/anthropometer/main/install.sh | sh` (или `brew tap arian-shamaei/anthropometer && brew install amtr`). Читает готовые транскрипты Claude Code — инструментировать ничего не нужно; клавиша `R` собирает PDF-отчёт с картами контекста и деревьями субагентов.

**Подвох.** ранний проект (★~17): TUI на Rust + движок на Python 3.9+; смотрит транскрипты локально, так что для облачных/командных сессий картина может быть неполной.

`cost-tokens · subagents · tips` · Источник: [github/arian-shamaei](https://github.com/arian-shamaei/anthropometer)

## 4. Serg1kk/agents: набор из 8 универсальных субагентов Claude Code под любой стек

**Зачем.** тем, кто хочет разложить работу по ролям и не писать определения субагентов с нуля под каждый проект.

**Как.** скопировать `*.md` в `.claude/agents/` проекта или в `~/.claude/agents/` глобально. Модели распределены осознанно: план-архитектор/ревьюер и дизайнер — на Opus, backend/db/frontend/qa — на Sonnet, devops — на Haiku.

**Подвох.** совсем свежий репо (★~7, всего 5 коммитов); «универсальность» = общие роли, под нетривиальный стек промпты всё равно придётся править; параллельный прогон восьми агентов множит расход токенов.

`subagents · workflows` · Источник: [github/Serg1kk](https://github.com/Serg1kk/agents)

## 5. FlowCrew: планировщик + параллельные кодеры + QA-гейты поверх Claude Code

**Зачем.** для долгих задач (ресёрч, рефакторинг, фича целиком), которые хочется запустить и уйти, но без фейкового «готово».

**Как.** `git clone https://github.com/cuibuaa/flow-crew.git && cd flow-crew && npm install && npm link`; репетиция `flowcrew rehearse examples/hello-research.brief.md`; поставить скиллы `./skills/install.sh` и запускать из Claude Code командой `/ship`. Итог помечается честно: shipped (проверено) / ceiling-hit / incomplete / failed; веб-дашборд с инбоксом апрувов на `localhost:3000`.

**Подвох.** нужен Node 22.5+, Linux/macOS/WSL2; «reality gates» надёжны ровно настолько, насколько вы прописали проверки; ранний проект (★~7).

`workflows · subagents · automation` · Источник: [github/cuibuaa](https://github.com/cuibuaa/flow-crew)

## 6. arcaneum: семантический и полнотекстовый поиск по коду и докам прямо из Claude Code

**Зачем.** тем, у кого большая база кода и документации и надо, чтобы агент находил нужное по смыслу и по точной фразе, а не грепал вслепую.

**Как.** `pipx install "https://github.com/cwensel/arcaneum/releases/download/v0.9.0/arcaneum-0.9.0-py3-none-any.whl"`, затем в Claude Code `/plugin install cwensel/arcaneum`. Команды дёргают CLI напрямую через Bash — отдельный MCP-сервер не нужен. Один прогон индексирует сразу в оба движка.

**Подвох.** ★~7 (нишевый инструмент, хоть и 505 коммитов); нужны развёрнутые Qdrant и MeiliSearch — это не «поставил и забыл», а инфраструктура под индексацию.

`skills · slash-commands · tips` · Источник: [github/cwensel](https://github.com/cwensel/arcaneum)

## 8. Бесплатный репозиторий, который заставляет Claude Code планировать, тестировать и ревьюить как инженер

**Зачем.** тем, у кого Claude Code бросается кодить без плана и потом ломает то, что работало — навязать ему инженерный цикл.

**Как.** видео Hyperautomation Labs (6 авг): ставится как набор слэш-команд/скиллов в `.claude/`, который прогоняет фазы «спланируй → напиши тест → реализуй → отревьюй»; это тот же паттерн, что Anthropic советует для TDD (сначала падающий тест, потом реализация под него).

**Подвох.** конкретный репозиторий и шаги — в ролике, звёзды в заголовке ≠ гарантия качества под ваш стек; дисциплина «план/тест/ревью» экономит переделки, но удлиняет каждый прогон и жжёт больше токенов.

## 9. CLAUDE.md vs Projects vs Memory: что где сохраняется в Claude Code

**Зачем.** тем, кто путается, куда класть правила проекта, а куда — личные заметки, и почему Claude «забывает» одно и помнит другое.

**Как.** коротко: CLAUDE.md — проектная «конституция», читается автоматически в начале сессии и коммитится в репозиторий (общее для команды); личное — в `~/.claude/`; Memory/Projects — надсессионный слой самого продукта. Правило: то, что должно пережить `/clear`, кладите в файл, а не в историю чата.

**Подвох.** статья обзорная: детали поведения Projects/Memory зависят от плана и версии клиента и меняются от релиза к релизу — сверяйтесь с актуальной докой.

`prompting · tips` · Источник: [blog/stacknotice](https://dev.to/stacknotice/claude-code-claudemd-vs-projects-vs-memory-which-persists-what-23d4)

## 10. Внутри «правил» Claude Code: как auto-режим на самом деле решает, что вам разрешить

**Зачем.** всем, кто включает auto-режим (с 14 августа он становится дефолтным) и хочет понимать, что агенту дозволят без спроса, а что — нет.

**Как.** суть: чтобы пройти опасное действие, надо назвать именно рискованный параметр (например, ветку для force-push) — «почини деплой» не авторизует деструктивную миграцию. Практика: по-настоящему жёсткий только `permissions.deny`; корпоративные политики задавайте через managed settings, а не «мягкими» правилами, которые перебиваются локально.

**Подвох.** статья — реверс-инжиниринг стороннего исследователя, не офиц. документация; логика «согласия» опирается на суждение модели о намерении — интерпретируемо, но не пуленепробиваемо, и пользователь видит лишь «Blocked by classifier» без причины.

`tips · automation` · Источник: [blog/highflame](https://www.highflame.com/blog/the-44kb-of-claude-codes-rulebook-you-cant-print/)

## 11. Один плагин — и в Claude Code, и в Codex: как не пересобирать AI-сетап под каждый инструмент

**Зачем.** тем, кто держит сразу и Claude Code, и Codex (или мигрирует между ними) и устал вести два набора конфигов.

**Как.** видео Hyperautomation Labs (6 авг): общий слой скиллов/команд оформляется как один плагин, который цепляется к обоим CLI; выигрыш — единый набор ваших наработок независимо от того, какой агент запущен сегодня.

**Подвох.** переносимость обычно частичная — у Claude Code и Codex разные модели плагинов и возможности; конкретика совместимости — в ролике, проверяйте, что именно переносится, а что придётся дублировать.

## 12. Как посадить Claude Code на дешёвую модель Kimi K3 и срезать счёт за рутину

**Зачем.** фрилансеру/соло-команде, у кого Claude Code съедает бюджет: рутину (мелкие правки, бойлерплейт) отдать дешёвой модели, дорогую звать только на важное.

**Как.** через релей Nebius: `curl -fsSL https://nebius-tf-relay.vercel.app/install.sh | sh`, затем `nebiusrelay configure` (или `export NEBIUS_API_KEY=...`), запуск `nebiusrelay claude` (алиас `nclaude`) и выбор модели через `/model` → Kimi K3.

**Подвох.** релей заявляет окно ~262K вместо миллиона — реальные лимиты зависят от провайдера; для чувствительных задач (безопасность, сложные миграции, архитектура, продакшн) автор прямо советует оставаться на модели с высокой уверенностью и сперва проверять сетап на read-only задачах.

`case-study · cost-tokens · tips` · Источник: [blog/arindam_1729](https://dev.to/arindam_1729/how-to-use-kimi-k3-with-claude-code-6oo)
