## 1. Auto mode становится режимом прав по умолчанию в Claude Code

**Зачем.** Всем, кто устал жать Enter на каждое разрешение и хочет непрерывной работы агента, но с защитой от разрушительных команд.

**Как.** Ничего делать не нужно — новые сессии Pro/Max/Team переключатся сами 14.08. Выйти из режима: Shift+Tab или дропдаун режима в CLI. Свой закреплённый дефолт не изменится; плата за классификатор для Pro/Max/Team отменена.

**Подвох.** Для Enterprise, API и облачных провайдеров (AWS/GCP) режим пока opt-in. В тестах классификатор ловил 89% опасных команд против 13.6% у людей — но это не 100%, слепо доверять нельзя.

`automation · workflows · tips` · Источник: [blog/Anthropic](https://claude.com/blog/auto-mode-default-in-claude-code)

## 2. Сессии Claude Code теперь пишут друг другу (ListAgents / SendMessage)

**Зачем.** Тем, кто держит несколько worktree/терминалов по одному репо: сессия, сделавшая breaking change или завершившая миграцию, сама уведомит другую.

**Как.** Обновиться до v2.1.224+, проверить достижимые сессии командой /list-agents (алиас /peers), затем попросить «расскажи сессии в другом терминале, что мы поменяли в API» — Claude сам вызовет ListAgents и SendMessage. Настройки: crossSessionInbound (accept/hold/refuse), isolatePeerMachines.

**Подвох.** Только macOS/Linux (в т.ч. WSL2), на нативном Windows нет; не на Bedrock/Vertex/Foundry. Передаётся только текст (не история и не файлы); между машинами Claude может лишь ОТВЕТИТЬ через Remote Control, инициировать переписку нельзя.

`subagents · workflows · automation` · Источник: [docs/Anthropic](https://code.claude.com/docs/en/cross-session-messaging)

## 3. Self-hosted: запуск облачных сессий Claude Code на своей инфраструктуре

**Зачем.** Командам на Team/Enterprise с требованиями комплаенса и доступом к внутренним сервисам, БД и реестрам — когда код нельзя выпускать наружу.

**Как.** Создать именованные окружения в admin-настройках claude.ai и развернуть раннеры (`claude self-hosted-runner`) на хостах внутри сети. Два режима: фиксированное число раннеров или автоскейл-оркестратор, поднимающий их по очереди сессий.

**Подвох.** Только Team/Enterprise, выключено по умолчанию, недоступно при ZDR. Нужны свои ресурсы на образы/обновления раннеров; сами промпты всё равно уходят в Anthropic на инференс.

`automation · ci-cd · workflows` · Источник: [blog/Anthropic](https://claude.com/blog/run-claude-code-sessions-on-your-own-compute)

## 4. Промптинг Opus 5: убрать из промптов ручную самопроверку

**Зачем.** Всем, кто перенёс на Opus 5 промпты и CLAUDE.md от прежних моделей: легаси-каркас самопроверки удорожает сессии в Claude Code без прироста качества.

**Как.** Удалить явные «include a final verification step», «use a subagent to verify». Глубину рассуждения крутить через /effort (low/medium/high/xhigh/max) — low/medium дают хорошее качество за долю токенов. Для code-review — просить сообщать обо всём и фильтровать отдельным проходом.

**Подвох.** Отключить thinking можно только при effort ≤ high (на xhigh/max вернётся ошибка 400). С выключенным thinking модель иногда пишет tool-call текстом или протекают внутренние XML-теги.

`prompting · cost-tokens · tips` · Источник: [docs/Anthropic](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5)

## 5. Manage costs: хук фильтрации тестов и вынос инструкций в скиллы

**Зачем.** Тем, у кого длинные сессии съедают лимит: многотысячный вывод тестов и раздутый CLAUDE.md уходят в контекст с каждым сообщением.

**Как.** Повесить PreToolUse-хук на Bash, переписывающий команду теста на `... 2>&1 | grep -A5 -E '(FAIL|ERROR|error:)' | head -100`. Держать CLAUDE.md < 200 строк, рабочие инструкции (PR-review, миграции) вынести в skills. Между несвязанными задачами — /clear (дешевле, чем /compact). Следить через /usage и /context.

**Подвох.** /compact сам по себе большой запрос (читает всю историю) — для чистого старта дешевле /clear. Agent teams в plan mode жгут ~7x токенов. Страница живая (описывает фичи вплоть до v2.1.222), точную дату правки не показывает.

`cost-tokens · hooks · skills · testing` · Источник: [docs/Anthropic](https://code.claude.com/docs/en/costs)

## 6. Планировщик в сессии: /loop и cron-инструменты Claude Code

**Зачем.** Тем, кто хочет повесить агента на интервал прямо из сессии, не поднимая внешний cron: следить за деплоем/CI, дочинивать PR, ставить одноразовые напоминания.

**Как.** `/loop 5m проверь, прошёл ли CI, и ответь на комментарии ревью` — фиксированное расписание; только промпт — Claude сам выбирает интервал (1мин–1час); пусто — встроенный maintenance-промпт или .claude/loop.md. Одноразовое: «напомни в 15:00 запушить релиз». Управление: «какие задачи запланированы?» / «отмени…».

**Подвох.** /loop только session-scoped: живёт пока сессия открыта и idle, восстанавливается через --resume, авто-истекает через 7 дней; пропущенные срабатывания не догоняются. Для durable без сессии — Routines, Desktop tasks или GitHub Actions.

`automation · workflows · ci-cd · slash-commands` · Источник: [docs/Anthropic](https://code.claude.com/docs/en/scheduled-tasks)

## 7. Claude Code v2.1.224: плагины из zip и снятие лимита в 200 сабагентов

**Зачем.** Тем, кто раздаёт внутренние плагины без маркетплейса/git (просто по ссылке на zip), и тем, у кого динамические workflow упирались в лимит сабагентов.

**Как.** Указать плагин-источник типа `archive` со ссылкой на zip и (желательно) закрепить SHA-256 для воспроизводимости. Лимит сабагентов на сессию теперь регулируется CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION (дефолт 200), а не жёстким капом; лимиты параллелизма и глубины остаются.

**Подвох.** Без SHA-256-пиннинга установка из внешнего zip небезопасна (можно подсунуть изменённый архив). Снятый кап убирает рантайм-обрыв, но неограниченный спавн бьёт по токенам/лимитам.

`automation · subagents · skills` · Источник: [docs/Anthropic](https://code.claude.com/docs/en/changelog#2-1-224)

## 8. Claude Code v2.1.225: лимит трат шлюза и запрос доверия к каталогу

**Зачем.** Командам с корпоративным шлюзом/бюджетом — понятнее, почему сессию отрезало и когда лимит сбросится; плюс защита от запуска агентов в непроверенных директориях.

**Как.** Настраивать ничего не нужно: при достижении лимита шлюза сообщение об использовании теперь явно указывает кап, время сброса и текст оператора. При открытии `claude agents` в непроверенном каталоге появится запрос подтвердить доверие.

**Подвох.** Это мелкое релизное улучшение (в основном UX сообщений об ошибках), а не крупная фича; полезно прежде всего в enterprise-развёртываниях со шлюзом.

`cost-tokens · automation · tips` · Источник: [docs/Anthropic](https://code.claude.com/docs/en/changelog#2-1-225)

## 9. Plan Mode в Claude Code: 4 фазы Explore → Plan → Implement → Commit

**Зачем.** Тем, кто делает многофайловые изменения и рефакторинги: план до правок ловит архитектурные ошибки за секунды вместо дорогой переделки уже написанного кода.

**Как.** Войти в Plan Mode: Shift+Tab (второе нажатие), либо /plan, либо `claude --permission-mode plan` (на Windows — Alt+M). Фазы Explore→Plan (без правок) → Implement (accept-edits/auto) → Commit (normal). План редактировать в редакторе через Ctrl+G. Для планирования Opus + исполнения Sonnet — /model opusplan.

**Подвох.** Правило одного предложения: если диф описывается одной фразой — план не нужен, иначе тратите токены. Слабый план = пробелы в CLAUDE.md. В статье упомянут /ultraplan, который в августовской v2.1.222 убрали.

`refactoring · workflows · prompting` · Источник: [blog/Mukesh Murugan](https://codewithmukesh.com/blog/plan-mode-claude-code/)

## 10. Хуки — гарантии, скиллы — знания, субагенты — контекст: как выбрать

**Зачем.** Тем, кто пихает обязательные правила в скиллы/промпты и удивляется, что модель их игнорирует ~10% раз: фреймворк подсказывает, что должно быть детерминированным хуком.

**Как.** Три вопроса-фильтра: «что обязано срабатывать всегда?» → хук (shell-скрипт, гарантия исполнения); «как мы тут делаем X?» → скилл (грузится по релевантности); «что заслуживает своего контекста/модели?» → субагент.

**Подвох.** Это концептуальный разбор, а не пошаговый туториал: готовых конфигов settings.json почти нет, придётся писать самому. Опубликовано 15.07, обновлено 02.08.

`hooks · skills · subagents · prompting` · Источник: [blog/Nick Liu](https://nick-liu.com/posts/claude-code-skills-hooks-subagents/)

## 11. Плагины Claude Code: слой-упаковка для скиллов, хуков, команд и MCP

**Зачем.** Тем, кто хочет превратить свои CLAUDE.md/скиллы/хуки/MCP в устанавливаемый пакет, который команда ставит за 30 секунд, а не копирует руками.

**Как.** Структура my-plugin/.claude-plugin/plugin.json + папки skills/agents/hooks + .mcp.json. Локально: `claude --plugin-dir ./my-plugin`. Из маркетплейса: `/plugin marketplace add your-org/claude-plugins` и `/plugin install deploy-tools@your-org-plugins`. Проверка: `claude plugin validate ./my-plugin`.

**Подвох.** Статья описывает базовую механику и не покрывает свежие августовские фишки (archive-источник из zip, мгновенную активацию плагинов без /reload-plugins).

`skills · hooks · slash-commands · mcp` · Источник: [blog/Feng (shiplight)](https://www.shiplight.ai/blog/claude-code-plugins)

## 14. Кейс: соло-мейкер собрал голосовое управление Claude Code (Audiochatty)

**Зачем.** Пример «построил-выложил за выходные» для соло-мейкеров; и для тех, кто хочет вести кодинг-сессии удалённо/руки-свободны.

**Как.** Плагин оборачивает Claude Code в псевдотерминал, каждые ~5 сек опрашивает новые голосовые инструкции, озвучивает резюме шага и голосом отвечает на запросы разрешений. Python 3 без внешних зависимостей (macOS/Linux), данные локально в ~/.audiochatty/ (права 0600).

**Подвох.** Зависит от бэкенда audiochatty.com для голоса; лицензия PolyForm Shield ограничивает коммерческое использование конкурентами; это нишевый dev-инструмент, а не бизнес-продукт.

`case-study · workflows · tips` · Источник: [github/tmshapland](https://github.com/tmshapland/audiochatty-plugin)
