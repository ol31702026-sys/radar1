## 1. Claude Code 2.1.222: worktree-сессии больше не тронут main деструктивным git

**Зачем.** Тем, кто гоняет несколько worktree-сессий и сабагентов параллельно по одному репозиторию и боится, что один агент снесёт незакоммиченное в основном checkout.

**Как.** Обновиться до 2.1.222+. Теперь worktree-изолированная сессия/сабагент не выполнит деструктивную git-команду (reset --hard, clean -fd, перезаписывающий checkout) против main checkout — только в своём worktree. Параллельно /usage перестал приписывать сабагентам и MCP-серверам чужой расход токенов, а экспериментальная ultraplan удалена.

**Подвох.** Защита действует только для worktree-изоляции — обычная сессия без worktree по-прежнему может выполнить деструктивный git. Если полагались на ultraplan — поведение изменится, фичи больше нет.

`workflows · subagents · tips` · Источник: [docs/Anthropic](https://code.claude.com/docs/en/changelog#2-1-222)

## 2. Claude Code 2.1.223: /review стал алиасом /code-review, хинт /teleport и фикс обхода прав

**Зачем.** Тем, кто ревьюит PR прямо из CLI и следит за безопасностью прав доступа агента.

**Как.** /review теперь алиас /code-review: вызов вида /code-review <уровень> <номер PR>, уровень ultra запускает глубокое облачное ревью ветки/PR. Добавлен хинт /teleport, чтобы подхватить облачную сессию локально; в plugin-marketplace заработали org-wildcards. Отдельно закрыта уязвимость с обходом проверки прав через Bash.

**Подвох.** Это запись из changelog — точные опции смотрите в доках. ultra-ревью идёт в облаке (расход и приватность кода). Старое /review оставили алиасом, но привыкать стоит к /code-review.

`slash-commands · ci-cd · tips` · Источник: [docs/Anthropic](https://code.claude.com/docs/en/changelog#2-1-223)

## 3. Claude Code 2.1.225: предупреждение показывает лимит расхода шлюза

**Зачем.** Тем, кто работает через корпоративный шлюз/прокси с лимитом расхода и хочет заранее видеть, сколько осталось, а не упираться в стену внезапно.

**Как.** Обновиться до 2.1.225+. Предупреждение об использовании теперь показывает информацию о лимите расхода шлюза: сам cap, время сброса и сообщение оператора. Команда claude agents теперь ведёт себя как claude — спрашивает про доверие к рабочему каталогу, если он не в списке доверенных.

**Подвох.** Информация о лимите приходит от вашего шлюза — без него показывать нечего. Это точечная полировка (usability/безопасность), а не крупная новая возможность.

`cost-tokens · automation · tips` · Источник: [docs/Anthropic](https://code.claude.com/docs/en/changelog#2-1-225)

## 4. Как обуздать флот сабагентов: лимиты глубины и бюджета в Claude Code

**Зачем.** Тем, кто разворачивает multi-agent пайплайны и боится рекурсивного взрыва спавна сабагентов и неконтролируемого счёта за токены.

**Как.** Статья разбирает лимиты из v2.1.217–219 с точными env-переменными: CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH (глубина вложенности), MAX_CONCURRENT_SUBAGENTS (сколько параллельно), MAX_SUBAGENTS_PER_SESSION (всего за сессию), плюс исправление флага --max-budget-usd — теперь он действительно прерывает работу при достижении лимита в долларах.

**Подвох.** Дефолты консервативные: под тяжёлые флоты их придётся осознанно поднимать вручную, иначе упрётесь в потолок. Конкретные значения меняются между версиями — сверяйтесь с актуальными доками.

`subagents · cost-tokens · automation` · Источник: [blog/Digital Applied](https://www.digitalapplied.com/blog/claude-code-subagent-depth-limits-budget-caps-2026)

## 5. Новая MCP-спека 2026-07-28: stateless-ядро — что меняется для Claude Code

**Зачем.** Тем, кто пишет или подключает MCP-серверы к Claude Code и хочет понять, что несёт спека от 28 июля.

**Как.** Ключевое — stateless: сессии без session id, каждый POST самоописательный (несёт _meta), что позволяет держать MCP-серверы serverless. Добавлены версионируемые расширения Apps и Tasks и авторизация OAuth 2.0/OIDC. Итог для Claude Code — более простые и дешёвые в эксплуатации коннекторы.

**Подвох.** Это разбор стороннего автора, а не официальная дока; миграция существующих stateful-серверов небесплатна. Официальный анонс Anthropic выходил отдельно — по деталям сверяйтесь с ним.

`mcp · ide-integration` · Источник: [blog/Yash Thakker](https://explainx.ai/blog/mcp-2026-07-28-stateless-spec-july-2026)

## 7. Skills в Claude Code: полный гид и когда что выбрать вместо hooks/subagents/MCP

**Зачем.** Тем, кто путается, что взять под конкретную задачу — skill, hook, subagent или MCP — и в итоге лепит не то.

**Как.** Гид даёт простой критерий выбора: hooks — когда нужна гарантия (срабатывает всегда), subagents — когда нужна изоляция контекста от основной сессии, MCP — когда нужен внешний доступ (API/данные), skills — когда нужно переиспользуемое ноу-хау/процедура. Разобрана структура SKILL.md и шаги установки.

**Подвох.** Материал во многом вечнозелёный и отчасти продвигает продукт Totalum; конкретику по установке и синтаксису всё равно сверяйте с официальными доками Claude Code.

## 8. Context engineering под Claude 5: чек-лист из 6 проходов и /doctor

**Зачем.** Тем, у кого CLAUDE.md разросся и куча скиллов, и под Claude 5 всё это стало скорее мешать модели, чем помогать.

**Как.** Чек-лист из 6 проходов для правильного размера контекста: (1) убрать конфликтующие инструкции, (2) выкинуть очевидное, (3) вынести повторяющееся в скиллы, (4) оставить по одному примеру-интерфейсу вместо десятка, (5) прогнать /doctor, (6) завести eval. Приведены конкретные списки «оставить / удалить».

**Подвох.** Совет заточен под Claude 5 (Opus 5 / Fable 5): на более старых или слабых моделях агрессивная обрезка контекста может, наоборот, навредить. Это мнение автора, а не официальный гайд Anthropic.

## 9. Веб-поиск в Claude Code жрёт токены — как это починить

**Зачем.** Тем, у кого веб-поиск в Claude Code неожиданно жжёт токены и раздувает контекст на ровном месте.

**Как.** Автор показывает, что обычный фетч затягивает в контекст всю страницу целиком. Фикс — прогонять веб-ресёрч через режим вопрос/JSON (на примере Firecrawl), где возвращается только релевантный ответ, а не сырой HTML. Это заметно снижает расход токенов на каждый поиск.

**Подвох.** Решение завязано на сторонний сервис Firecrawl (ключ, лимиты, приватность — запросы уходят наружу). Для разовых задач встроенного WebFetch может хватить и без него.

## 10. Во сколько реально обходится флот параллельных агентов Claude

**Зачем.** Тем, кто прикидывает бюджет перед тем, как запускать флот параллельных сабагентов, и хочет не переплачивать за Opus везде.

**Как.** Разобрана раскладка по моделям: тир-флот из 1×Opus 5 (сложное) + 3×Sonnet 5 (основная работа) + 1×Haiku (мелочь) обходится примерно в $39/день против ~$81/день на all-Opus — около −52%, если распределять задачи по сложности.

**Подвох.** Цифры — усреднённая прикидка (материал обновлён 31 июля, исходно июньский); ваш реальный расход зависит от объёма контекста и типа задач. Тир-раскладка требует ручной настройки, кто на какой модели сидит.

`cost-tokens · subagents · workflows` · Источник: [blog/Developers Digest](https://www.developersdigest.tech/blog/what-parallel-claude-agents-actually-cost)

## 11. token-savior: MCP-сервер для навигации по коду и памяти между сессиями

**Зачем.** Тем, кто устал, что Claude Code читает файл целиком ради одной функции и теряет контекст между сессиями.

**Как.** `pip install "token-savior-recall[mcp]"`, прописать сервер в MCP-конфиг Claude Code (профиль optimized, WORKSPACE_ROOTS). Даёт ~15 инструментов: find_symbol()/get_function_source() для точечной навигации по коду, память в SQLite между сессиями, оптимизацию Bash-команд. Бенчмарк на 96 задачах (Opus): 97.9% (188/192) против 78.3%, −80% активных токенов, −83% времени.

**Подвох.** Автор честно пишет, что бенчмарк-репозиторий сейчас недоступен — цифрам верить «по методу», а не как независимо воспроизводимым. MIT, нужен Python 3.11+; гибридный векторный поиск требует доп. зависимостей.

`mcp · cost-tokens` · Источник: [github/Mibayy](https://github.com/Mibayy/token-savior)

## 12. raptor: превращает Claude Code в security-агента (Semgrep/CodeQL + LLM)

**Зачем.** Пентестерам и security-командам, кто хочет собрать из Claude Code автономного агента для поиска уязвимостей в коде и бинарях.

**Как.** `git clone` + `pip install -r requirements.txt` + Claude Code + Semgrep (или Docker-образ). Решения принимает Claude Code (через CLAUDE.md, скиллы, команды, агенты), исполнение — Python: Semgrep (123 правила), CodeQL (8 запросов), дедуп, SARIF. Примеры: `/scan /path` (без LLM, минуты), полный `/agentic --threat-model --validate` (10–30 мин, лимит ~$10/прогон).

**Подвох.** Авторы прямо: «не отполированный софт, держится на энтузиазме и скотче». Генерация эксплойтов/патчей — beta/alpha и ненадёжна на дешёвых моделях; CodeQL запрещает коммерческое использование. Инструмент dual-use — запускать только против целей, на которые есть авторизация.

`skills · subagents · automation` · Источник: [github/gadievron](https://github.com/gadievron/raptor)

## 13. brigade: заставляет агентов доказывать сделанную работу

**Зачем.** Тем, кто устал слышать от агента «тесты прошли, ничего не сломал» без доказательств, и хочет аудируемый след.

**Как.** `pipx install brigade-cli` + `brigade setup`. Команда `brigade work verify run --target . --command "pytest -q" --capture brigade-work` реально запускает проверку и пишет receipt-файл с настоящим exit code, длительностью и дельтой код-графа — подделать нельзя. Встроенный код-граф на Rust показывает, кто что вызывает; один каталог .brigade/mcp.json синхронит MCP-серверы/инструменты на 19 харнессов (Claude Code, Cursor, Codex…); заметки-хендоффы проходят гейт ревью.

**Подвох.** Ранняя стадия («движемся быстро», возможны ломающие изменения). Нет фонового демона — вызывать нужно явно (cron/CI/агент). Это не память-как-сервис и не автопубликатор: ничего не пушит и не промоутит без явного одобрения. MIT.

`mcp · skills · workflows` · Источник: [github/escoffier-labs](https://github.com/escoffier-labs/brigade)

## 14. Кейс: мобильная игра за 85 часов на подписке Claude Code за $100

**Зачем.** Соло-разработчикам и мелким командам — трезво прикинуть отдачу от подписки $100 и понять, что даёт дисциплина, а что — модель.

**Как.** Инженер с 8 годами опыта за 85 часов и ~месяц (1 июля — 4 авг) собрал мобильную игру Kombat. Приёмы: архитектуру и критические куски (игровая логика, WebSocket, стейкинг) держал за собой, спеки писал markdown-файлами (не в чате), Claude Code реализовывал код; обязательный тест-сьют и лог багов, куда ИИ записывал найденное. Итог: 58 696 строк, 296 коммитов за 34 сессии, iOS closed beta.

**Подвох.** Оценки «800 часов без ИИ» и «$60–250k подрядчикам» — прикидки автора, не проверяемый факт. Работал опытный инженер с ревью критичных мест; новичок без этого получит другой результат. Игра пока в закрытой бете, не в проде.

## 15. Кейс: агентство из Мадрида пересобрало свой многоязычный сайт с Claude Code

**Зачем.** Небольшим агентствам и студиям — как своими силами тянуть многоязычный сайт без отдельных переводчиков и подрядчиков на рутину.

**Как.** Мадридское агентство Soamee пересобрало свой сайт (Astro 5 + Tailwind v4, 345 постов, 115 кейсов, 5 языков) с Claude Code: 331 из 639 коммитов помечены `Co-Authored-By: Claude`. ИИ сделал систему переводов и 400-строчный скрипт их проверки, повторяющиеся компоненты, middleware нормализации URL, генератор sitemap, черновики постов. Переводы — за секунды вместо дней, вспомогательные скрипты — за часы.

**Подвох.** Каждое изменение всё равно проходило ручную проверку — без ревью так не работает. Это кейс от самого агентства (по сути само-презентация); «52% коммитов с Claude» не равно «52% сложной работы».

`case-study · automation · workflows` · Источник: [blog/Soamee](https://soamee.com/en/blog/en-we-built-website-with-claude-code)
