## 1. Claude Code v2.1.232: форкинг подагентов включён по умолчанию

**Что нового.** Версия 2.1.232 (13 августа): форкинг подагентов стал режимом по умолчанию. Добавлена возможность писать другим сессиям через @имя-сессии. Имена сессий уникальны. Breaking change: Todo/Task-инструменты отключены на Opus 4.8+ — включить через CLAUDE_CODE_ENABLE_TODO_TOOLS=1.

**Зачем вам.** Если вы автоматизируете задачи с параллельными потоками (сбор, обработка, запись) — агентный режим включён из коробки. @-упоминание позволяет агенту-сборщику отправлять результаты агенту-записывателю без настройки IPC.

**Как попробовать.** Запустите claude agents в 2.1.232+ — форкинг уже активен. Если использовали Todo-инструменты с Opus 4.8+, добавьте CLAUDE_CODE_ENABLE_TODO_TOOLS=1 в .env или CLAUDE.md.

## 2. Claude Code v2.1.234: автопродолжение сессии после сброса лимита токенов

**Что нового.** Версия 2.1.234 (17 августа): автопродолжение сессии после сброса лимита управляется через /config. Переменная CLAUDE_CODE_PROJECT_DIR_NAME задаёт имя папки транскриптов для конкретного проекта. Кейбайндинг selection:clear. Security fix: пути Windows NT-namespace отклоняются в файловых операциях.

**Зачем вам.** Полезно для длинных автоматизированных прогонов — сборы данных или обработка документов — которые раньше зависали при достижении лимита. CLAUDE_CODE_PROJECT_DIR_NAME позволяет не смешивать транскрипты разных проектов.

**Как попробовать.** Обновите: npm update -g @anthropic-ai/claude-code. В /config найдите пункт про лимиты и включите автопродолжение. Для раздельных транскриптов: CLAUDE_CODE_PROJECT_DIR_NAME=myproject в .env.

**Как попробовать.** Нужен Team или Enterprise план. Команда claude self-hosted-runner --help покажет параметры. Для кросс-машинных сообщений убедитесь, что обе машины на 2.1.224+.

## 4. Anthropic: официальный гайд по эффективному использованию сессий Claude Code

**Что нового.** Официальный блог Anthropic (14 августа): /clear начинает чистую сессию для отдельных задач; /compact сжимает историю перед паузой (дешевле, пока кэш активен); /context показывает что загружено; @file.txt прикрепляет файл без лишнего Read-вызова; /rewind откатывает ходы без сброса кэша; MAX_THINKING_TOKENS=0 отключает размышление на сессию.

**Зачем вам.** Правильный порядок команд снижает стоимость прогона на 30-40% при тех же результатах. Если вы запускаете регулярные задачи — этот гайд объяснит, почему длинная сессия вдруг начинает работать медленнее.

**Как попробовать.** Прочитать: claude.com/blog/maximizing-the-value-of-your-claude-code-sessions. Добавить quiet-флаги в CLAUDE.md для команд с большим выводом. Запускать /loop в отдельной сессии — ключевой совет из статьи.

`новости-claude - возможности - ai` - Источник: [Anthropic](https://claude.com/blog/maximizing-the-value-of-your-claude-code-sessions)

## 5. ББР Банк: ИИ-аналитик вместо штатного — дайджесты и соцсети за 5 мин в день

**Бизнес.** ББР Банк — российский банк, специализирующийся на продаже драгоценных металлов. Отдел продаж требовал ежедневного мониторинга рыночных новостей.

**Процесс.** Подготовка ежедневных рыночных дайджестов для отдела продаж + ведение страниц в ВКонтакте и Макс.

**Было.** Штатный новостной аналитик: оклад + взносы около 150 000 руб/мес. Ручной мониторинг 20+ источников по драгметаллам и 15 источников для соцсетей.

**Сделали.** Подключили ИИ-сервис Give Me Public в режиме human-in-the-loop: сервис мониторит источники и готовит контент, сотрудник утверждает перед публикацией.

**Стало.** 3–5 минут в день на модерацию вместо полного рабочего дня аналитика. 80% постов выходят без правок. Стоимость подписки в разы дешевле зарплаты специалиста.

**Инструменты.** Give Me Public — облачный ИИ-сервис для мониторинга источников и контент-генерации.

**Как повторить.** 1) Составить список источников по отрасли. 2) Выбрать ИИ-сервис мониторинга с human-in-the-loop. 3) Настроить: модератор за 5 минут просматривает готовый контент. 4) Пробный режим 2–4 недели.

**Подвох.** Сервис готовит сырой контент — нужен человек с отраслевой экспертизой. В финансовой тематике ИИ может пропустить существенную ошибку.

## 6. Caitlyn Minimalist: ИИ-агент поддержки — ответ за 23 секунды вместо часа

**Бизнес.** Caitlyn Minimalist — интернет-магазин кастомизированных украшений (гравировка имён, дат, символов). 30 000+ обращений в поддержку ежемесячно.

**Процесс.** Обработка входящих вопросов о статусе заказов, доставке, подарочной упаковке, кастомизации. Однотипные вопросы отнимали большую часть времени команды.

**Было.** Среднее время первого ответа: 1 час 1 минута. Большинство обращений требовало участия живого оператора.

**Сделали.** Внедрили Gorgias AI Agent: агент обрабатывает типовые вопросы, сложные передаёт оператору.

**Стало.** Время первого ответа: 23 секунды (−99.37%). Время решения: −58.96%. Однотрогательные решения: +303.88%. Конверсия через ИИ-ассистент: 20%.

**Инструменты.** Gorgias — AI-платформа для e-commerce поддержки со встроенным AI Agent.

**Как повторить.** 1) Выгрузить топ-20 входящих вопросов. 2) Настроить базу знаний: FAQ, доставка, возвраты, кастомизация. 3) Запустить агента, мониторить 2 недели. 4) Расширять зону ответственности постепенно.

**Подвох.** Для кастомных товаров ИИ может давать неточные ответы без детальной настройки базы знаний. При 30K+ обращений/мес даже 1% ошибок — 300 недовольных клиентов.

## 7. Стоматология Dr Claire: ИИ-ресепшн — ноль пропущенных звонков, +44% записей

**Бизнес.** Стоматологическая клиника Dr Claire — два администратора. Высокая нагрузка в часы пик: обед и конец рабочего дня.

**Процесс.** Приём входящих звонков, квалификация пациентов, запись на приём, интеграция с расписанием.

**Было.** 47% входящих звонков уходили в пропущенные — когда оба администратора были заняты. Потенциальные пациенты переходили к конкурентам.

**Сделали.** Внедрили ИИ-ресепшн: агент принимает звонок, задаёт вопросы, бронирует слот в расписании. Нестандартные случаи переключает на человека.

**Стало.** Пропущенных звонков: 0 (было 47%). Записей на приём: +44%.

**Инструменты.** AI-ресепшн с интеграцией в систему управления клиникой (конкретный продукт в источнике не указан).

**Как повторить.** 1) Выгрузить статистику пропущенных звонков, найти часы пиковой нагрузки. 2) Выбрать AI-телефонию с поддержкой нужного языка. 3) Записать сценарии: запись, перенос, отмена, цена. 4) Запустить как overflow — перехватывает только когда оба заняты.

**Подвох.** Пациенты старшего возраста могут плохо воспринимать разговор с ботом. Настройка занимает 2–4 недели. Без интеграции с учётной системой записи нужно дублировать вручную.

## 8. Логистика: CRM-автоматизация — обработка заказа 15 мин вместо 32, ошибки в 8 раз реже

**Бизнес.** Логистическая компания (название не указано в источнике), управление грузовыми рейсами. Кейс от интегратора МАЙПЛ.

**Процесс.** Обработка заказов: подтверждение рейса, поиск документов, коммуникация с клиентами и водителями. До автоматизации — ручные операции в разных системах.

**Было.** Время обработки заказа: 32 минуты. Ошибок в партии: 8. Стоимость рейса: 18 000 руб. Потеря заявок: до 10%.

**Сделали.** Внедрили CRM с интеграциями: 1С для учёта, GPS-мониторинг для рейсов, IP-телефония. Автоматизировали маршрут заявки от приёма до отгрузки.

**Стало.** Время обработки: 15 мин (−53%). Ошибок: 1 (−87.5%). Стоимость рейса: 12 000 руб. (−33%). Потеря заявок: ~0. ROI 180–320% за год, окупаемость 4–6 мес.

**Инструменты.** CRM Битрикс24 или AmoCRM + интеграции: GPS-мониторинг, 1С, IP-телефония. Срок внедрения: 2–4 месяца.

**Как повторить.** 1) Замерить время обработки заявки пошагово. 2) Выбрать CRM с нативной интеграцией с 1С. 3) Начать с одного процесса: приём и подтверждение рейса. 4) Добавить GPS-мониторинг вторым шагом.

**Подвох.** Внедрение 2–4 месяца — настройка идёт на живой системе. Интеграция с 1С требует программиста 1С или интегратора. Сотрудники могут сопротивляться изменениям.
