## 1. Claude Code 2.1.238: keybindingFlavor, заголовки в запросах, --defer-shutdown и 15+ фиксов

**Что нового.** Версия 2.1.238 от 20 августа 2026. Добавлено: (1) настройка keybindingFlavor в /config — выбор раскладки (emacs/vim/default); (2) headersHelper — добавить произвольные заголовки к API-запросам Claude; (3) --defer-shutdown для self-hosted runner — сервис дожидается окончания активных сессий перед завершением; (4) proxy auth в self-hosted окружениях. Исправлен критический memory leak в длинных сессиях. Ещё 15+ багов.

**Зачем вам.** keybindingFlavor нужен тем, кто держит Vim-хоткеи на мышечной памяти и раньше приходилось перестраиваться. headersHelper — для корпоративных gateway с кастомными заголовками аутентификации. Фикс memory leak критичен для длинных агентных прогонов: сессия больше не «толстеет» со временем. --defer-shutdown позволяет безопасно деплоить self-hosted runner без обрыва текущих сессий.

**Как попробовать.** Обновите: npm install -g @anthropic-ai/claude-code. keybindingFlavor — в /config → Keyboard. headersHelper — в /config. Self-hosted --defer-shutdown: флаг при запуске сервера. Фикс memory leak работает автоматически после обновления.

## 2. Claude Code 2.1.234: CLAUDE_CODE_PROJECT_DIR_NAME, значок в GitLab MR и авторесуме по лимиту

**Что нового.** Версия 2.1.234 от 17 августа 2026. Добавлено: (1) CLAUDE_CODE_PROJECT_DIR_NAME — переменная окружения с именем директории текущего проекта; доступна в хуках и скриптах; (2) значок статуса Claude Code прямо в интерфейсе GitLab merge request — видно, что агент работает; (3) авторесуме сессии после сброса rate limit — сессия сама возобновляется без ручного перезапуска. Исправлены критические ошибки стабильности.

**Зачем вам.** CLAUDE_CODE_PROJECT_DIR_NAME нужна тем, кто использует хуки или скрипты с разным поведением в разных проектах — теперь не надо парсить путь вручную через basename. Значок в GitLab MR полезен командам, у которых Claude Code запущен в CI. Авторесуме снимает необходимость следить за завершением ночных задач при исчерпании квоты API.

**Как попробовать.** Обновите Claude Code. CLAUDE_CODE_PROJECT_DIR_NAME доступна автоматически в хуках (echo $CLAUDE_CODE_PROJECT_DIR_NAME). GitLab MR значок появляется при интеграции Claude Code с GitLab. Авторесуме по лимиту работает автоматически после обновления.

## 3. Claude Code 2.1.228: фикс прокрутки экрана, Git на Windows и перезапись файла без чтения

**Что нового.** Версия 2.1.228 от 11 августа 2026. Исправлено и добавлено: (1) критический фикс screen redraw — прокрутка в длинных сессиях больше не «расползалась» и не смещала вывод; (2) исправлена работа Git на Windows с Extended-length путями и UNC-путями; (3) улучшены межсессионные сообщения — более надёжный протокол доставки; (4) исправлена аутентификация Vertex AI credentials (токен не истекал корректно); (5) Write tool теперь разрешает перезапись существующего файла без предварительного чтения на новых моделях (opus-4.8+, sonnet-4.6+).

**Зачем вам.** Прокрутка экрана в длинных сессиях была болезненной — особенно при /ultrareview и многошаговых рефакторингах. Фикс Git на Windows снимает проблему для пользователей WSL-окружений с длинными путями. Перезапись без чтения ускоряет агентные пайплайны, которые генерируют и пишут много файлов подряд.

**Как попробовать.** Обновите Claude Code. Все исправления применяются автоматически. Write без чтения работает на моделях claude-opus-4-8 и claude-sonnet-4-6 и новее — старые модели по-прежнему требуют Read перед Write.

## 4. Anthropic: Computer Use, Browser Use Tool, Skills API и Files API — всё в GA

**Что нового.** Анонс 20 августа 2026. Четыре инструмента перешли из беты в GA: (1) Computer Use — несколько действий за один вызов вместо одного, HIPAA-совместимость, ~30% снижение стоимости рабочих процессов; (2) Browser Use Tool — новый инструмент для веб-агентов: сочетает скриншоты и DOM-структуру страницы, надёжнее пиксельного позиционирования; (3) Skills API — загружать «папки инструкций», которые Claude подключает по требованию, запускаются в code execution sandbox; (4) Files API — автоудаление по сроку, 5× выше rate limit, 1 ТБ на организацию. Бета-заголовки API больше не нужны.

**Зачем вам.** Для бизнес-пайплайнов, где агент заполняет формы или перемещается по порталам — Browser Use Tool надёжнее скриншотов: он видит структуру DOM, а не пиксели. Skills API избавляет от повторной загрузки одних и тех же инструкций в каждый промпт. Files API позволяет загрузить документ один раз и ссылаться на ID во всех запросах — не гонять одни мегабайты снова и снова. Один реальный пример из анонса: страховой claims-воркфлоу сократился с 32 до 13 минут.

**Как попробовать.** Удалите бета-заголовок anthropic-beta: computer-use-2024-10-22 — Computer Use теперь в стандартном API. Browser Use Tool: заменяет инструмент bash_20250124. Files API: /v1/files без бета-заголовка, auto-expiry настраивается. Skills API и Files API также доступны через Microsoft Foundry. Документация: platform.claude.com/docs.

## 5. TechNio Solutions (Дубай): n8n-автоматизация маркетинга — лид за 2 мин вместо 20 часов, 14 ч/нед

**Бизнес.** TechNio Solutions — IT-сервисная компания, малый бизнес, Дубай (ОАЭ). Предоставляют услуги цифровой трансформации и разработки.

**Процесс.** Маркетинговые операции: обработка входящих лидов, рассылка email-кампаний, публикации в соцсетях, сборка аналитических отчётов — всё делалось вручную командой.

**Было.** Время ответа на новый лид: до 20 часов (нерабочее время, выходные). Команда тратила ~14 часов в неделю на рутинные маркетинговые операции. Отчёты собирались руками с ошибками.

**Сделали.** Построили несколько n8n-воркфлоу: (1) автоматический ответ на лид в течение 2 минут через webhook + квалификационные вопросы; (2) email-кампании по расписанию с персонализацией через SMTP-ноду; (3) автопостинг в соцсети; (4) ежедневный KPI-отчёт без участия человека.

**Стало.** Время первого ответа лиду: 20 ч → менее 2 минут. Конверсия лид→встреча: +31%. Высвобождено 14 ч/нед команды. Открываемость email: +22%. Вовлечённость в соцсетях: +18%. Нулевые ошибки в 12 подряд отчётах.

**Инструменты.** n8n (self-hosted, open source) — оркестратор воркфлоу. Все интеграции через нативные ноды n8n без дополнительных платных сервисов.

**Как повторить.** 1) Установить n8n (self-hosted на VPS или n8n.cloud). 2) Воркфлоу «новая форма → немедленный ответ»: webhook → условие → email-нода. 3) Email-последовательности через SMTP-ноду. 4) Соцсети: нода Buffer или прямые API. 5) Отчёты: Google Sheets нода + Telegram-нотификация.

**Подвох.** N8n требует VPS для self-hosted (от $5/мес) или облачной подписки. Первоначальная настройка воркфлоу: 1–2 дня. Без мониторинга воркфлоу могут упасть тихо — нужна нода уведомления об ошибках в Telegram/email.

## 6. ВинПроф (производство металлоконструкций): 1С-автоматизация — запасы −40%, расчёты за минуты

**Бизнес.** ВинПроф — производство профилей для стальных конструкций, 3 производственные площадки, около 10 000 м², мощность до 6 000 изделий в год. Малый/средний бизнес, Россия. Кейс — победитель конкурса «1С:Реальная автоматизация 2025».

**Процесс.** Производственный учёт и управление материалами: учёт стальных заготовок, расчёт раскроя (пересчёт кг в погонные метры), контроль складских остатков, синхронизация с бухгалтерией.

**Было.** Расчёты раскроя — вручную, несколько дней на партию. Складские остатки без партионного учёта: неизвестно, какая сталь куплена когда и по какой цене, образовывался «мёртвый» запас.

**Сделали.** Внедрили 1С:УНФ (Управление нашей фирмой) с интеграцией 1С:Бухгалтерии. Партионный учёт стали: каждая партия сырья отслеживается по ID от прихода до изделия. Поставили сканирование штрихкодов/этикеток на производстве. Автоматизировали пересчёт кг ↔ погонные метры в заказах.

**Стало.** Складские запасы стали: −40% (партионный учёт выявил избытки и дал точные данные для закупки). Время расчёта раскроя: с нескольких дней до нескольких минут. Данные из производства мгновенно видны в бухгалтерии.

**Инструменты.** 1С:УНФ + 1С:Бухгалтерия + USB-сканеры штрихкодов + печать этикеток из 1С.

**Как повторить.** 1) 1С:УНФ заменяет Excel-учёт и даёт партионный учёт «из коробки». 2) Настроить пересчёт единиц измерения (кг↔м/шт) под специфику производства. 3) Любой USB-сканер штрихкодов + этикетки, напечатанные из 1С. 4) Стандартный обмен данными между УНФ и Бухгалтерией.

**Подвох.** Внедрение 1С с нуля требует партнёра-франчайзи: от 100–300 тыс. руб. «под ключ» с обучением. Перенос накопленных данных из Excel — отдельная задача. Партионный учёт требует дисциплины персонала: каждая приёмка должна оформляться своевременно, иначе картина снова расплывается.
