## 1. Claude Code 2.1.232: форкинг субагентов по умолчанию и упоминание сессий через @

**Что нового.** Версия 2.1.232 (13 августа 2026): форкинг субагентов включён по умолчанию — каждый `fork`-субагент наследует весь контекст разговора и prompt cache родителя без дополнительной настройки. Добавлен ввод `@` для упоминания другой открытой сессии Claude Code по имени. В `/config` появились строки для настройки срока истечения диалогов и кросс-сессионных сообщений. Устранена уязвимость обхода разрешений через PowerShell и Windows symlink. Всего 40+ исправлений.

**Зачем вам.** Форкинг даёт субагентам полный контекст «из коробки»: если вы запускаете параллельные задачи — анализ файлов, генерацию отчётов, обработку заявок — каждый агент сразу знает все детали. @-упоминание сессий позволяет строить мультиагентные цепочки прямо в интерфейсе без кода и конфигов.

**Как попробовать.** Обновите Claude Code до 2.1.232+. Форкинг активен автоматически. Для @-упоминания введите `@` в строке диалога — появится список активных сессий. Настройки диалогов — в `/config` → `dialogExpiry` и `crossSessionMessages`. Доступно на всех тарифах.

## 2. Claude Code 2.1.234: сессия сама продолжается после сброса лимита, GitLab MR в футере

**Что нового.** Версия 2.1.234 (17 августа 2026): сессии Claude Code автоматически продолжают прерванный turn после сброса лимита usage на claude.ai. Добавлены: бейдж GitLab Merge Request в нижней панели, переменная окружения `CLAUDE_CODE_PROJECT_DIR_NAME` (переопределяет имя рабочей директории), биндинг клавиши `selection:clear`. Безопасность: устранена уязвимость к NTLM credential-leak. Всего 30+ исправлений.

**Зачем вам.** Если Claude Code в середине длинной задачи — обработка массива файлов, генерация документов — упирался в дневной лимит и приходилось вручную перезапускать контекст, теперь он сам возобновит работу после сброса. Особенно важно для фоновых и ночных задач, которые вы не мониторите в реальном времени.

**Как попробовать.** Обновите до 2.1.234+. Автовозобновление работает без настроек — просто оставьте задачу выполняться. Переменную `CLAUDE_CODE_PROJECT_DIR_NAME` задайте в `.env` для переопределения имени директории в интерфейсе.

## 3. Claude Code 2.1.237–238: стиль «Лаконично», readline-клавиши и headersHelper в плагинах

**Что нового.** 2.1.237 (19 августа): исправлен сброс кеша промптов в сессиях через LLM-шлюз или кастомный `base_url`; добавлен встроенный стиль вывода «Concise» («Лаконично»). 2.1.238 (20 августа): настройка `keybindingFlavor: readline` для клавиш Ctrl-A/E/K/W в терминале; `headersHelper` в плагин-маркетплейсе для динамической генерации HTTP-заголовков; флаг `--defer-shutdown-max-min` для self-hosted runners; исправлена утечка памяти в долгих сессиях. 30+ исправлений.

**Зачем вам.** Стиль «Concise» полезен когда Claude Code подробно объясняет очевидное — активируйте и получайте только результат. `keybindingFlavor: readline` — для тех, кто привык к Emacs-клавишам в терминале. Исправление кеша промптов важно при использовании API-прокси или LLM-шлюза: раньше кеш неожиданно сбрасывался, увеличивая стоимость.

**Как попробовать.** Обновите до 2.1.238+. Стиль «Concise» выберите через `/style`. В настройки (`~/.claude/settings.json`) добавьте `"keybindingFlavor": "readline"`. При кастомном `base_url` — кешировение теперь работает корректно автоматически.

## 4. Claude Code 2.1.239: команда /claude-api upgrade и учёт стоимости data-residency

**Что нового.** Версия 2.1.239 (21 августа 2026): команда `/claude-api upgrade` автоматически переводит Python-проект с пакета `anthropic` 0.x на 1.x — находит устаревшие вызовы, предлагает и применяет правки. Оценки стоимости включают множитель ×1.1 для data-residency рабочих пространств (US-only inference). В Cloud Sessions синхронизированные плагины отмечаются как `name@synced`. На Alpine/musl-сборках Linux заработали нативная вставка изображений, буфер обмена и захват аудио. Исправлено зависание при старте за HTTPS-прокси с Bedrock/SSO и стриппинг Content-Type в прокси Bedrock. 50+ исправлений.

**Зачем вам.** Если вы автоматизировали процессы через anthropic Python SDK и ещё не перешли на версию 1.x — `/claude-api upgrade` сделает это одной командой. Учёт надбавки data-residency позволяет видеть реальную стоимость запросов до отправки.

**Как попробовать.** Обновите до 2.1.239+. В корне Python-проекта с `anthropic` введите `/claude-api upgrade` — Claude Code покажет план и применит изменения. На Alpine/musl системах проверьте буфер обмена и вставку изображений после обновления.

## 5. B2B-компания: автоквалификация лидов в Bitrix24 — ответ за 30 секунд вместо 2–3 часов

**Бизнес.** B2B-компания, ~4 менеджера в отделе продаж, ~400 лидов в месяц из 5 каналов (сайт, мессенджеры, лид-формы, партнёры). Сфера не раскрыта. Россия.

**Процесс.** Первичная квалификация входящих лидов в Bitrix24: менеджеры вручную разбирали поток, задавали уточняющие вопросы, заполняли карточку.

**Было.** Среднее время первого ответа — 2–3 часа. ~70% заявок нецелевые. Около 150 горячих лидов ежеквартально терялись из-за задержки. Менеджеры тратили 5–6 часов в день на базовый разбор.

**Сделали.** Асинхронный AI-агент на FastAPI + Redis: принимает вебхуки из Bitrix24 с дедупликацией (Redis-локи), задаёт клиенту первичные квалификационные вопросы, заполняет карточку, передаёт тёплый лид менеджеру. LLM — GPT-5.

**Стало.** Время первого ответа: 30–40 секунд. Доля квалифицированных лидов: +35%. Экономия рабочего времени менеджеров: ~50 часов в месяц. За 6 недель пилота (~400 заявок) потерянных горячих лидов не зафиксировано.

**Инструменты.** FastAPI, Redis, GPT-5 (API), Bitrix24 webhooks, Python (Pydantic, httpx, tenacity).

**Как повторить.** 1) Настройте вебхуки из Bitrix24 на свой эндпоинт. 2) Напишите агента: получает обращение → задаёт 3–4 квалификационных вопроса → заполняет поля CRM. 3) Добавьте дедупликацию через Redis (ключ = contact_id + timestamp). 4) Запустите пилот на одном канале, через 2 недели смотрите метрики.

**Подвох.** GPT-5 через API — линейные расходы при росте объёма заявок, считайте бюджет заранее. Агент может ошибиться при нестандартных форматах контакта. Без мониторинга сбоев вебхука вы не узнаете о потерянных лидах.

## 6. Стартап LeaderChat: чат-поддержка на LLM — стоимость обработки лида упала в 10 раз

**Бизнес.** LeaderChat — SaaS-стартап (Россия), 3 человека в режиме part-time. Разрабатывают и эксплуатируют платформу автоматизации чатов поддержки и продаж для МСБ-клиентов.

**Процесс.** Обработка входящих обращений клиентов через Telegram, VK, MAX и веб-виджет: ответ на типовые вопросы, квалификация лидов, маршрутизация на живого оператора при необходимости.

**Было.** Живые операторы обрабатывали все диалоги. ~90% обращений — повторяющиеся типовые вопросы. Значительные расходы на найм, обучение и контроль персонала. Классические чат-боты не справлялись с вариативностью формулировок.

**Сделали.** Перевели обработку на собственную LLM-платформу: модель отвечает на типовые вопросы 24/7, подбирает продукт или услугу, маршрутизирует нестандартные случаи на специалиста. Интегрировали с Telegram, VK, MAX и веб-виджетом.

**Стало.** Стоимость обработки одного лида снизилась примерно в 10 раз. Чистая прибыль компании: 100–150 тыс. руб./мес (цель — 500 тыс. руб./мес). Существующие клиенты сохранены при реструктуризации продукта.

**Инструменты.** LLM-модели через API (конкретная модель не раскрыта), Telegram Bot API, VK API, платформа MAX, веб-виджет.

**Как повторить.** 1) Соберите 100–200 реальных диалогов поддержки и выявите топ-20 повторяющихся вопросов. 2) Настройте LLM-агента с базой ответов. 3) Задайте правило эскалации: уверенность < 80% или нестандартный вопрос → живой оператор. 4) Запустите в одном канале, отслеживайте долю автоматически закрытых обращений.

**Подвох.** Около половины расходов компании уходит на оплату LLM — при росте объёма диалогов это линейный рост затрат. Нужен мониторинг галлюцинаций модели в ответах клиентам: неправильный ответ стоит дороже, чем ошибка оператора.

## 7. Just AI: рассылка для конференции — 30 минут вместо 8 часов, 100% доставка в банки

**Бизнес.** Just AI — российская компания (диалоговый ИИ, 101–200 сотрудников). Дважды в год проводит конференцию Conversations с 500–700 участниками.

**Процесс.** Персональная рассылка участникам: каждому нужно отправить уникальные ID доступа и ссылку на трансляцию за несколько дней до события.

**Было.** Ручная многоэтапная работа: синхронизация таблиц, выгрузка/загрузка в приложение конференции, контроль новых регистраций. От 2 часов в спокойный день до 8+ часов в пиковые предконференционные дни. 30% писем не доходило до сотрудников банков и госучреждений (спам-фильтры). Более 30 входящих запросов «пришлите ссылку» ежедневно перед событием.

**Сделали.** Три автоматизированных workflow на Just AI Agent Platform: сбор участников из вспомогательных источников, проверка и присвоение уникальных ID/ссылок, персонализированная отправка через собственный SMTP (минуя сторонние рассылочные сервисы).

**Стало.** Доставляемость на корпоративные домены банков и госструктур — 100%. Ручная работа сократилась до 30 минут в день. Входящих запросов «где моя ссылка» — единицы вместо 30+. Экономия минимум 50 000 руб. по сравнению с конкурентными решениями.

**Инструменты.** Just AI Agent Platform, Google Sheets (синхронизация данных), собственный SMTP-сервер, HTML-шаблоны писем.

**Как повторить.** 1) При клиентах-банках или госструктурах переходите на отправку через собственный SMTP. 2) Разделите workflow: сбор данных → проверка и обогащение → отправка. 3) Добавьте проверку «уже отправлено» чтобы не дублировать при повторных запусках.

**Подвох.** Собственный SMTP требует репутации домена и корректных SPF/DKIM/DMARC-записей — без этого письма так же попадут в спам. Just AI Agent Platform — коммерческий продукт; для простых рассылок дешевле n8n или Make.

## 8. Финансовый брокер: AI-реактивация 319 «спящих» контактов — $49 000 выручки без рекламы

**Бизнес.** Финансовый брокер (долговое консультирование), малый бизнес. Конкретные размеры и страна в источнике не указаны.

**Процесс.** Работа со списком «спящих» контактов из CRM — клиенты, с которыми связь прервалась и которых команда давно списала как нерабочих.

**Было.** 319 контактов в CRM отмечены командой как «мёртвые» и не обрабатывались. Ресурсов на ручной охват не было.

**Сделали.** Запустили AI-кампанию реактивации: многоканальные касания через SMS и email. AI-агент вёл начальный диалог, квалифицировал ответившего, передавал «тёплого» лида живому специалисту с полным контекстом переписки.

**Стало.** $49 000 выручки из списанных контактов. Рекламный бюджет: $0. Точные сроки кампании и конверсионная воронка в источнике не раскрыты.

**Инструменты.** Conversational AI для SMS и email (конкретный продукт не назван в источнике).

**Как повторить.** 1) Выгрузите из CRM контакты без активности 3+ месяца, которые когда-то проявляли интерес. 2) Сегментируйте: были заинтересованы, но «ушли в молчание». 3) Настройте AI-агента для первичного контакта с персонализацией под контекст. 4) Порог передачи живому менеджеру: ответил на 2+ сообщения → передаём с историей диалога.

**Подвох.** В источнике не указаны сроки кампании и конверсионная воронка — верифицировать эффективность самостоятельно нельзя. Эффект сильно зависит от качества данных в CRM. Без согласия на рассылку — юридические риски (152-ФЗ для РФ, GDPR для ЕС).

## 9. Стоматологическая клиника: AI-ресепшн — ноль пропущенных звонков, запись пациентов +44%

**Бизнес.** Стоматологическая клиника, 2 регистратора. Точное местоположение в источнике не раскрыто. Малый бизнес.

**Процесс.** Ответ на входящие звонки, запись пациентов на приём, ответы на типовые вопросы (стоимость, часы работы, свободные слоты).

**Было.** 47% входящих звонков оставались без ответа: регистраторы не успевали в пиковые часы и после закрытия клиники. Потенциальные пациенты уходили к конкурентам.

**Сделали.** Внедрили голосового AI-ресепшниста: принимает звонки 24/7, квалифицирует обращение, записывает пациента в расписание, интегрируется с системой учёта клиники.

**Стало.** Пропущенных звонков — 0% (было 47%). Записей на приём: +44%. Оба регистратора перераспределили время на работу с пациентами в клинике.

**Инструменты.** Voice AI (конкретный продукт в источнике не назван), интеграция с системой расписания.

**Как повторить.** 1) Оцените долю пропущенных звонков (лог АТС или CRM). 2) Выберите voice AI с интеграцией в вашу МИС или CRM (в РФ — Aimylogic, SberSalute, Robin, Sipuni с AI-модулем). 3) Настройте сценарии: запись → подтверждение → напоминание за сутки. 4) Оставьте переход на живого сотрудника для нестандартных ситуаций.

**Подвох.** Часть пациентов некомфортно записывается к врачу через голосового бота — ожидайте процент отказов. В России медицинские данные регулируются 152-ФЗ — убедитесь в соответствии. Конкретный инструмент не назван: потребуется самостоятельный выбор и тестирование.
