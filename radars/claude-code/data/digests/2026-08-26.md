## 1. Claude Code 2.1.243: промпт-кэш на 1 час, modelPicker, -70 МБ RAM за сессию

_Релиз 25 августа: настройка промпт-кэша до 1 часа (вместо 5 минут), кастомный список моделей в /model, нативный установщик 75 МБ вместо 340 МБ, каждая сессия расходует на 40–70 МБ RAM меньше._

**Что нового.** Версия 2.1.243 (25 августа). Новые настройки: `promptCacheTtl` — держит промпт-кэш главной беседы 1 час (subagent'ы — 5 мин); `subagentPromptCacheTtl` — отдельно для агентов; `modelPicker` — формируй упорядоченный список с метками для меню `/model`; `modelPricing` — подтягивает контрактные цены организации вместо публичных. В `/usage` появился «Loops breakdown»: число прогонов, токены на прогон, последний запуск. Нативный установщик: ~75 МБ (zstd) против 340 МБ. Бинарник на 2 МБ меньше. Каждая сессия расходует на 40–70 МБ RAM меньше.

**Зачем вам.** Час промпт-кэша — прямая экономия токенов в automation-сессиях: большой системный промпт (шаблоны документов, инструкции, список товаров) не пересчитывается каждые 5 минут. Для VPS с несколькими параллельными агентами минус 70 МБ на сессию ощутимо. Loops breakdown помогает понять, какой loop сжигает больше всего токенов и денег.

**Как попробовать.** `claude update` до 2.1.243. В `.claude/settings.json` добавь `"promptCacheTtl": 3600` для 1-часового кэша. `modelPicker` настраивается там же. Loops breakdown смотри в `/usage`.

## 2. Claude Code 2.1.232: сессии общаются через @-упоминание, subagent fork по умолчанию

_С 13 августа пишешь @session-name в промпте — Claude находит другую живую сессию и отправляет ей сообщение. Subagent-fork наследует полный контекст и кэш, неинтерактивные spawn'ы уходят в фон автоматически._

**Что нового.** Версия 2.1.232 (13 августа). `@-mention`: пишешь `@имя-сессии` в промпте — Claude через `ListAgents` находит живую сессию и `SendMessage` посылает ей сообщение. `subagent_type: fork` теперь включён по умолчанию: дочерний агент наследует весь контекст + промпт-кэш. Неинтерактивные spawn'ы в интерактивных сессиях уходят в фон сами. В `/config` — настройки «Dialog expiry» и «Messages from your other sessions».

**Зачем вам.** Несколько специализированных сессий могут координироваться без вашего участия: агент-документов отправляет результат агенту-кода, тот проверяет и отвечает. Fork-subagent экономит токены в разветвлённых workflow — контекст не пересылается заново.

**Как попробовать.** Запусти сессии с именами: `claude --session-name doc-agent` и `claude --session-name code-agent`. В одной напиши: `@code-agent: проверь изменения в schema.py`. Настройки входящих сообщений — в `/config` — Messages from your other sessions.

**Что нового.** С мая 2026 действовал временный прирост +50% к еженедельным лимитам использования Claude Code. Anthropic продлевал его четыре раза. 19 августа 2026 продление не последовало — лимиты вернулись к базовым значениям.

**Зачем вам.** Если Claude Code стал чаще выдавать «Usage limit reached» — это не баг, а возврат к норме. Два окна: 5-часовое и еженедельное. Планируй тяжёлые сессии с учётом этих окон. С 2.1.243 в `/usage` появился Loops breakdown — видно, сколько токенов уходит по каждому циклу.

**Как попробовать.** Проверь расход в `/usage`. Планы: Pro ($20/мес) — базовый объём; Max 5x ($100/мес) — 5x лимит; Max 20x ($200/мес) — 20x. Для интенсивной automation рассмотри Max. Официальные лимиты: claude.com/pricing.

## 4. Claude Code 2.1.239: /claude-api upgrade мигрирует Python-проект с SDK 0.x на 1.x

_С 21 августа встроенная команда /claude-api upgrade автоматически находит и исправляет несовместимости в Python-проекте при переходе с anthropic SDK 0.x на 1.x — включая изменившиеся таймауты._

**Что нового.** Версия 2.1.239 (21 августа). Новая команда `/claude-api upgrade`: Claude Code читает Python-проект, находит несовместимости с anthropic SDK 1.x (в 1.x таймауты используют `anthropic.Timeout` вместо `httpx.Timeout`, ряд других breaking changes) и применяет исправления. Обновлён skill `claude-api` для API 1.x.

**Зачем вам.** Если у вас написана автоматизация на `anthropic` 0.x — миграция на 1.x требует поправить несколько мест в коде. `/claude-api upgrade` делает это автоматически: не нужно читать release notes SDK и искать вхождения вручную.

**Как попробовать.** В папке проекта запусти `claude` — введи `/claude-api upgrade`. Работает для Python-проектов с `import anthropic`. После — проверь `git diff`, убедись в корректности, и только затем коммить.

## 5. Велоmotos: интеграция 1С с маркетплейсами — заказы за 15 мин вместо 3 ч, -13 млн ФОТ

**Бизнес.** Производитель велосипедов, квадроциклов и мотоциклов. Продажи через маркетплейсы (WB, Ozon и др.) + обязательная маркировка «Честный Знак».

**Процесс.** Загрузка заказов из личных кабинетов маркетплейсов в 1С, синхронизация остатков, обработка отчётов, интеграция с «Честным Знаком» — всё вручную.

**Было.** 2–3 часа ежедневно на ручную обработку заказов. Склад: 800 заказов/день. Масштабирование = расширение штата.

**Сделали.** Внедрили RDV Market: автоматическая загрузка заказов из маркетплейсов в 1С, синхронизация остатков в реальном времени, автообработка отчётов, интеграция с «Честным Знаком».

**Стало.** Обработка: 2–3 ч → 15 мин (в 10 раз быстрее). Пропускная способность: 800 → 1500 заказов/день. Рост FBS-продаж: в 3 раза. Ассортимент: +50%. Управленческая отчётность: в 3 раза быстрее. Экономия ФОТ: 13 млн руб.

**Инструменты.** 1С + RDV Market (система управления маркетплейсами на базе 1С) + «Честный Знак».

**Как повторить.** 1) Замерить время на ручную работу в каждом кабинете маркетплейса. 2) Выбрать систему 1С-интеграции (RDV Market, МойСклад, Synchrozon, RetailCRM). 3) Стартовать с одного маркетплейса, добавить остальные после стабилизации. 4) «Честный Знак» планировать отдельно.

**Подвох.** Кейс опубликован на партнёрском ресурсе — вендорский акцент возможен. Сумма 13 млн руб. без детализации периода. Интеграция с «Честным Знаком» добавляет сложности для нестандартных категорий.

## 6. Застройщик ЖК: AI-менеджеры в мессенджерах — ФОТ с 300 до 80 тыс., конверсия +16 п.п.

_Девелопер с 4 жилыми комплексами внедрил AI-менеджеров в WhatsApp и Telegram: ФОТ отдела продаж с 300 до 80 тыс. руб./мес., конверсия с 65% до 81%, ответ за 30 секунд вместо 4 часов, годовая экономия 2,6 млн руб._

**Бизнес.** Строительная компания — 4 проекта ЖК в работе, оборот ~800 млн руб./год. Отдел продаж: 6 менеджеров.

**Процесс.** Приём входящих заявок (WhatsApp, Telegram, сайт), первичная квалификация, ответы на типовые вопросы о квартирах, запись на показ.

**Было.** ФОТ менеджеров: 300 тыс. руб./мес. + налоги (около 400 тыс. итого). 40% заявок поступало после 18:00 и в выходные — без ответа. Из 100 заявок обрабатывалось 60–65. Среднее время ответа: 4 часа. За год сменились 4 из 6 менеджеров.

**Сделали.** Разработали 4 AI-менеджера (по одному для каждого ЖК). Обучили на 100+ реальных диалогах лучших менеджеров. Интегрировали с WhatsApp Business API, Telegram Bot API, сайтом и CRM.

**Стало.** ФОТ: 300 → 80 тыс. руб./мес. Конверсия: 65% → 81%. Время ответа: 4 ч → 30 сек. 100% заявок обрабатывается 24/7. Годовая экономия: 2,6 млн руб. Окупаемость: 1 месяц.

**Инструменты.** LLM-агенты + WhatsApp Business API + Telegram Bot API + CRM. Разработка: 130 тыс. руб. за один ЖК.

**Как повторить.** 1) Собрать 50–100 диалогов лучших менеджеров. 2) Обучить агента. 3) Запустить в режиме ассистента рядом с менеджером на 2–3 недели. 4) Перевести в автономный режим.

**Подвох.** Кейс публикует разработчик (aibotmanager.ru) — нет независимой верификации, название компании скрыто. AI не заменяет менеджера для переговоров и изменений в договоре. Нестандартные ситуации требуют ручной эскалации.

**Сделали.** За 2 месяца обучили LLM на своей базе: шаблоны договоров, прецеденты, письма, типовые ответы. Юрист получает черновик и тратит 5–10 минут на проверку.

**Процесс.** Четыре потока: приём и обработка лидов, email-кампании, публикации в соцсетях (LinkedIn, Facebook, Instagram), еженедельная отчётность из 5 систем.

**Сделали.** Построили n8n-workflow: автозахват лидов, дедупликация + обогащение через Clearbit API, скоринг по отрасли и размеру компании, немедленный персонализированный ответ.
