## 1. Claude Code 2.1.246: просмотр правил Auto mode и 35+ исправлений надёжности

**Что нового.** В команде `/permissions` добавлена вкладка Auto mode — можно видеть и редактировать правила, по которым Claude Code решает, требовать ли подтверждение для каждого инструмента. В статус-строке теперь отображается время завершения хода (например `✻ done 6:05 PM`). В `/tasks` видна модель и уровень усилий каждого subagent. Устранено критическое замедление transcript при наличии очень длинных строк (base64 и т.п.) — они теперь отображаются усечёнными. Также исправлено удаление пользовательских git worktrees при очистке фоновых сессий и ошибки MCP с аргументами в виде JSON-строк вместо реального типа.

**Зачем вам.** Вкладка Auto mode меняет подход к безопасным автоматизированным запускам: теперь видно, какие правила действуют, и можно тонко настроить их под свой проект — без постоянных интерактивных подтверждений, но и без полного отключения sandbox. Исправление замедления transcript критично для сессий, работающих с кодом, данными или выводом, содержащим base64.

**Как попробовать.** Обновите Claude Code: `claude update`. Откройте `/permissions`, переключитесь на вкладку «Auto mode». Для просмотра задач агентов с детализацией модели: `/tasks`.

## 2. Claude Code 2.1.243: 1-часовой кеш промптов, кастомный список моделей и вход без API-ключа

**Что нового.** Добавлены управляемые настройки: `promptCacheTtl` и `subagentPromptCacheTtl` — кеш промптов теперь можно держать 1 час (вместо 5 минут по умолчанию); `modelPicker` — курируемый список моделей в `/model` пикере с метками и порядком; `modelPricing` — contracted per-model rates организации. Добавлен keyless sign-in: `/login → Anthropic Console` для организаций без API-ключей. Улучшено время запуска: sandbox и MCP больше не блокируют первый фрейм. Loops breakdown в `/usage` — история и токены per-loop. Размер нативного инсталлера сокращён с 340 МБ до ~75 МБ (zstd), потребление памяти снижено на 40–70 МБ.

**Зачем вам.** `promptCacheTtl: 3600` при длинных повторяющихся сессиях даёт реальную экономию токенов — в 12 раз меньше циклов перезаписи кеша. Для команд: `modelPicker` позволяет выдать коллегам только одобренный список моделей. Keyless вход удобен для внутренних deployments без раздачи API-ключей.

**Как попробовать.** В `~/.claude.json` (или managed settings): `"promptCacheTtl": 3600`. Keyless вход: запустите `claude`, введите `/login`, выберите «Anthropic Console». Кастомный пикер: добавьте секцию `modelPicker` в настройки организации.

## 3. Claude Code 2.1.232: subagent forking по умолчанию и @mentions между сессиями

**Что нового.** Subagent forking включён по умолчанию — новые subagent стартуют быстрее за счёт форка существующего процесса. Добавлены @mentions: можно обратиться к другой Claude-сессии по имени прямо из текста; `SendMessage` доставляет сообщение к «голому имени» живой сессии; `ListAgents` теперь показывает активных соседей. Интерактивные сессии на одной машине получили уникальные имена (при дубле добавляется `my-session (2)`). Поддержка GitLab MR URL в флаге `--worktree`. Добавлена secret redaction для GitLab token families.

**Зачем вам.** @mentions — это primitiv для мульти-агентной координации: одна сессия-«диспетчер» может ставить задачи другим именованным сессиям прямо в prompt или через инструменты. Forking по умолчанию ускоряет `/workflows` с несколькими subagent. Для тех, кто держит параллельные сессии в одном проекте — теперь не нужно угадывать, какая сессия что делает.

**Как попробовать.** Обновите: `claude update`. Запустите две сессии, узнайте имена через `/list-agents`. В первой: `SendMessage("session-name-2", "выполни задачу X")`. Форкинг включён автоматически, ничего делать не нужно.

## 4. Claude Code 2.1.236–237: ANTHROPIC_DEFAULT_MODEL и встроенный стиль Concise

**Что нового.** `ANTHROPIC_DEFAULT_MODEL` (2.1.236, 19 авг) — переменная окружения, задающая модель по умолчанию для всех сессий. `notify_when_idle` в `SendMessage` (2.1.236) — уведомление при простое целевой сессии. Wildcard read-deny rules (`**/.env`) на macOS в sandbox. Встроенный стиль вывода «Concise» (2.1.237, 20 авг) — укорочённые ответы без конфигурации. Исправлен prompt caching для сессий с LLM gateway или custom base URL.

**Зачем вам.** `ANTHROPIC_DEFAULT_MODEL=claude-haiku-4-5-20251001` в `.env` проекта или CI — быстрое переключение между моделями без изменения кода. Для конвейеров, где Claude Code используется как инструмент: теперь модель можно параметризовать снаружи. Стиль Concise полезен для длинных задач, где Claude обычно много «объясняет» — меньше шума в выводе.

**Как попробовать.** Установите в `.env` или CI-конфиге: `ANTHROPIC_DEFAULT_MODEL=claude-sonnet-4-6`. Стиль Concise: в активной сессии введите `/style concise` или добавьте в CLAUDE.md строку `Отвечай кратко по делу.`

## 5. Маркетинговое агентство Layer: отчёт клиенту 10 часов → 20 минут с Claude и Supermetrics

**Бизнес.** Layer — норвежское digital-агентство. Специализация: performance-маркетинг для клиентов, данные из нескольких рекламных и аналитических платформ одновременно.

**Процесс.** Создание нестандартных клиентских отчётов: когда данные из нескольких каналов (Google Ads, Facebook, Analytics и др.) нужно свести в один документ, а стандартные дашборды Looker Studio не покрывают кастомные вопросы клиентов.

**Было.** До 10 часов на один нестандартный отчёт. Работа сводилась к ручному извлечению данных из каждой платформы, объединению в таблицах и написанию интерпретации.

**Сделали.** Подключили Supermetrics для автоматического сбора данных из всех каналов → передают данные в Claude для анализа и генерации выводов → итоговый текст форматируют в Google Sheets. Перед внедрением AI Lead агентства Morten Kleven «несколько недель жёстко валидировал данные» из Supermetrics в Claude.

**Стало.** 20 минут на отчёт (из них 17 минут — ручное форматирование в Google Sheets). Сбор и анализ данных: несколько минут. «За весь период тестирования не нашли ни одной галлюцинации» (Morten Kleven, AI and Automation Lead).

**Инструменты.** Claude (Anthropic), Supermetrics, Looker Studio, Google Sheets.

**Как повторить.** 1) Подключите Supermetrics к своим рекламным/аналитическим платформам. 2) Настройте экспорт данных в структурированный формат (CSV, Google Sheets). 3) Подготовьте prompt для Claude с шаблоном нужного отчёта и вставляйте данные. 4) Начните с одного типа отчёта, валидируйте данные 2-3 недели, прежде чем масштабировать.

**Подвох.** 17 из 20 минут уходит на ручное форматирование в Google Sheets — это узкое место, которое не автоматизировано. Supermetrics стоит денег (~$99+/мес). Валидация данных до доверия займёт несколько недель активного использования.

## 6. LeaderChat: команда из 3 человек автоматизировала поддержку клиентов — стоимость лида 10x ниже операторов

**Бизнес.** LeaderChat — российская команда из 3 человек (part-time), SaaS-платформа для автоматизации чатов поддержки и продаж для бизнесов. Клиенты — компании разных отраслей, например туристические агентства. Стабильная прибыль без внешнего финансирования.

**Процесс.** Обработка входящих клиентских обращений в мессенджерах и виджетах сайта: Telegram, ВКонтакте, MAX, веб-виджет. До 90% вопросов — одни и те же: цена, оплата, доставка, выбор услуги.

**Было.** Компании держали штатных операторов для повторяющихся консультаций. Традиционные сценарные чат-боты не справлялись из-за негибкой логики — слишком много вариантов вопросов.

**Сделали.** Разработали отдельный сервисный слой поверх существующей архитектуры LeaderChat, не переписывая всё с нуля. Интегрировали LLM API для генерации ответов. Бот обрабатывает типовые вопросы, сложные случаи автоматически эскалирует живому оператору с накопленным контекстом диалога. Работает во всех каналах параллельно.

**Стало.** Стоимость обработки лида снизилась в 10 раз по сравнению с живыми операторами. Чистая прибыль команды: 100–150 тыс. руб./мес. (цель — 500 тыс./мес.). Ни один из существующих клиентов не ушёл при переходе на AI. «Около 90% обращений состояли из одних и тех же вопросов» — это и стало точкой входа.

**Инструменты.** Собственная платформа LeaderChat, LLM API (конкретная модель в источнике не указана), Telegram Bot API, ВКонтакте API, MAX API.

**Как повторить.** 1) Проанализируйте свои входящие обращения — выявите TOP-20 повторяющихся вопросов. 2) Начните с одного канала (например Telegram). 3) Интегрируйте LLM для генерации ответов по шаблонам. 4) Настройте эскалацию на оператора при обнаружении сложного запроса. 5) Отслеживайте долю ошибочных ответов и итерируйте промпты.

**Подвох.** «Около половины затрат приходится на оплату LLM и инфраструктуры» — при росте трафика расходы на модели могут съесть маржу. Потребуется время на обучение и настройку промптов под конкретный бизнес. Эскалация сложных случаев работает только если настроена корректная классификация «сложно/просто».

## 7. Стоматология Dr Claire: AI-рецепционист обнулил пропущенные звонки и добавил 44% записей

**Бизнес.** Частная стоматологическая клиника Dr Claire — малая медицинская практика (страна в источнике не указана).

**Процесс.** Обработка входящих звонков для записи на приём и ответов на часто задаваемые вопросы.

**Было.** 47% входящих звонков оставались без ответа — в пиковые часы приёма, вечером и в выходные администратор не успевал или не работал. Потерянные звонки = потерянные пациенты.

**Сделали.** Внедрили AI-рецепциониста для обработки вызовов в нерабочее время и пиковые периоды. Бот отвечает на звонки, отвечает на типовые вопросы (часы работы, услуги, страховка), записывает на приём.

**Стало.** Пропущенных звонков — 0. Записей на приём: +44%. Нагрузка на администратора снизилась в пиковые часы.

**Инструменты.** AI-рецепционист Octavius AI (конкретная модель в источнике не указана).

**Как повторить.** 1) Проанализируйте статистику пропущенных звонков по времени суток и дням недели. 2) Определите «мёртвые зоны» — периоды, когда звонки не обрабатываются. 3) Подключите AI-ответчик именно для этих периодов (не для всех звонков сразу). 4) Обучите бот на FAQ вашей практики. 5) Настройте эскалацию на живого оператора для сложных случаев.

**Подвох.** Конкретные стоимость и инструменты в кейсе не раскрыты — источник это маркетинговый материал Octavius AI (поставщика решения). Метрики достоверны по структуре, но независимой проверки нет. Подходит для практик с чётким графиком и стандартными вопросами; нестандартные случаи всё равно требуют человека.

## 8. Финансовый брокер James: $49 000 из «мёртвой» базы CRM — без рекламного бюджета

**Бизнес.** James — финансовый брокер, специализация: консолидация долгов. Малый бизнес (страна в источнике не указана, по контексту — США/Канада).

**Процесс.** Реактивация спящих контактов в базе CRM — клиентов, которых ранее пометили как «потерянных» и перестали обрабатывать.

**Было.** 319 контактов в CRM помечены командой как нецелевые или нереальные. Ни один из них не получал коммуникаций. Потенциальная выручка де-факто «потеряна» — без затрат на реактивацию казалось нецелесообразно.

**Сделали.** Запустили многоканальную AI-кампанию реактивации (SMS + email). AI обрабатывал первый контакт, входящие ответы и квалификацию лидов — решал, кто из «мёртвых» контактов реально заинтересован. Только квалифицированных лидов передавал человеку.

**Стало.** $49 000 восстановленной выручки из базы, которую команда считала бесперспективной. Нулевые расходы на рекламу — работа только с уже существующей базой.

**Инструменты.** AI-платформа Octavius AI (конкретные модели в источнике не указаны), SMS-канал, email.

**Как повторить.** 1) Выгрузите из CRM контакты со статусом «потерян», «не отвечает», «холодный» — базу старше 6+ месяцев. 2) Сегментируйте по причине потери (цена, время, конкурент). 3) Создайте персонализированные шаблоны реактивации под каждый сегмент. 4) Настройте AI-квалификацию ответов — «горячих» передавайте менеджеру, «холодных» в долгую воронку. 5) Цель первого контакта — не продажа, а восстановление диалога.

**Подвох.** Источник — маркетинговый материал Octavius AI; независимой верификации нет. Персональные данные в CRM требуют соответствия GDPR/152-ФЗ при массовых рассылках. Базы старше 2-3 лет могут содержать устаревшие контакты — риск попасть в спам.
